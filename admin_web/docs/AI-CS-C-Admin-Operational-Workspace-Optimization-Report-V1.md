# AI-CS C Admin Operational Workspace Optimization Report V1

## 1. Current C Admin Experience Review

### 运营工作台

- 原页面使用真实 `/api/v1/admin/overview`、平台健康检查以及资料、质量、反馈列表数据，但标题强调“今天”，现有接口不能证明数据属于当天。
- 原页面主要呈现店铺、商品、SKU、FAQ 等目录总量，不能直接回答运营当前要处理什么、商品处于什么生命周期阶段、AI 是否可用。
- 原页面把全量资料、质量和反馈记录数量当作工作信号，统计口径对运营下一步指导不足。

### 商品知识中心

- 现有接口已经提供商品资料状态、客服状态、AI 知识状态和商品级发布证据。
- 原商品卡片会默认展示知识覆盖度和 RAG chunk 数等技术信息，但没有明确告诉运营下一步应该审核、启用还是发布。
- 当前 `ProductKnowledgeListItem` 不包含图片字段，因此本次没有虚构商品图片或占位统计。

### 导入中心

- 六个 Excel 模板均为现有静态正式资产，下载链接真实存在。
- 原页面已有模板说明和下载，但新用户只有三步提示，也没有明确区分“商品知识导入已支持”和另外五类“模板可下载、批量导入开发中”。
- R009 上传审核位于独立的“资料上传与审核”页面，本次保持该边界。

### AI 状态

- 现有接口真实提供 AI 服务、模型配置、可检索知识数量、启动后运行指标、评测和诊断信息。
- 原默认区仍偏技术视角，模型名和运行指标优先于业务结论。
- 当前接口不提供精确 collection 名称和服务版本，本次明确显示“当前接口未提供”，不伪造信息。

## 2. 优化后结构

### 运营工作台首页

首页现在按四个业务区域回答三个核心问题：

1. **当前工作**：待审核资料、知识缺口、待处理 AI 问题、未关闭运营建议，全部来自现有接口。
2. **商品生命周期**：资料已审核、客服可用、AI 知识已发布，以中文业务语义展示当前商品快照。
3. **快捷操作**：上传商品资料、查看商品、处理知识问题、查看 AI 状态，全部跳转现有路由。
4. **AI 状态**：展示 AI 服务、知识检索、回答能力和需要关注事项；平台健康异常单独呈现。

接口失败时显示“暂无法读取”或真实错误，不用 `0` 伪装失败；页面不再展示无法证明的“今日新增/今日完成”。

### 商品知识中心

- 默认卡片只突出商品名称、资料状态、客服状态、AI 知识状态和下一步动作。
- 下一步根据现有状态给出：完成资料审核、核对商品来源、启用客服使用、等待同步、重新同步或发布 AI 知识。
- 商品资料摘要和 SKU 信息进入默认折叠的“查看商品资料摘要”。
- chunk、embedding、collection、fingerprint、错误码和收据说明进入默认折叠的“查看技术证据”。
- 原审核、批量启用、发布和详情路由均保留，没有新增自动动作。

### 导入中心

- 保留六个模板卡片及六个原下载链接。
- 商品知识采集模板显示“导入已支持”；另外五个显示“模板可下载 / 批量导入功能开发中”。
- 新用户引导调整为：下载模板 → 填写商品资料 → 上传审核 → 查看结果。
- 下载不再被店铺选择遮挡；准备上传时仍需进入原 R009“资料上传与审核”页面确认目标店铺。

### AI 状态

- 默认摘要为：AI 服务、知识、回答能力、需要关注。
- 默认业务说明强调 AI 回答条件、商品生命周期状态和人工确认边界。
- 模型、知识查询范围、运行指标、提示词版本和异常证据保留在默认折叠的“高级技术信息”。
- 不可用或读取失败时显示真实原因，不展示虚假正常值。

## 6. 未解决问题

1. 商品列表接口没有图片字段，因此商品知识卡片暂不展示图片；需要未来接口正式提供后才能实现。
2. A 控制面接口没有返回精确 collection 名称和服务版本，技术展开区只能明确标注“当前接口未提供”。
3. 首页只有当前快照，没有时间序列接口，因此不展示今日、趋势或完成率。
4. 完整 Activation Receipt 和 AI Publication Receipt 仍在商品详情中查看，首页卡片只保留业务状态与下一步。

这些限制不影响现有业务流程，也没有通过前端构造虚假数据规避。
