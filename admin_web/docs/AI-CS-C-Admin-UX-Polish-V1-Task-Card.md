# AI-CS C Admin UX Polish V1 任务卡

## 任务

AI-CS C Admin UX Polish V1

## 目标

基于 C Admin Operational Workspace Optimization V1，在不改变接口、数据、权限和业务流程的前提下，统一运营工作台、商品知识中心、导入中心和 AI 状态页面的加载、成功、空和失败体验，使每个非成功状态都清楚回答“发生什么、为什么、下一步怎么办”。

## 基线与分支

- 基线：`f50ab0ac4f11b3170a8f615a1b466a6dcb3d5400`
- 分支：`codex/c-admin-ux-polish-v1`
- 允许路径：`admin_web/**`
- 目标 Gate：`C_ADMIN_UX_POLISHED_V1`

## 范围

- 统一四个目标页面的加载、空数据、失败和成功提示结构与中文文案。
- 强化现有下一步操作入口，只跳转已有路由或重试已有读取动作。
- 优化运营工作台、商品知识中心、导入中心与 AI 状态之间的业务返回和继续处理路径。
- 补充对应前端测试与隔离浏览器回归证据。

## 不包含

- API、数据库、migration、contracts、R006、R009、A/RAG、Prompt、Runtime 或 B 修改。
- 新接口、新字段、新业务模块、新权限、新统计口径或自动业务动作。
- 以 `0`、空数组或成功文案掩盖接口错误。

## 状态体验规则

1. 发生什么：先给出当前状态结论。
2. 为什么：说明真实数据来源、缺少条件或接口错误，不推测根因。
3. 下一步怎么办：提供重试、返回、继续准备或进入现有处理页面的明确入口。
4. 加载态不提前显示成功或空数据。
5. 空态与失败态严格区分；成功态只使用已返回的真实数据。

## 成功标准

1. 四个目标页面均覆盖加载、成功、空和失败状态。
2. 非成功状态包含状态结论、原因说明和一个可执行的既有下一步。
3. 页面间跳转使用现有路由，旧路由和原业务操作保持兼容。
4. 状态提示使用统一中文业务术语，不暴露内部字段名。
5. `pnpm test`、`pnpm typecheck`、`pnpm build` 和隔离浏览器四页面回归通过。

## 风险与缓解

- 错把空数据当失败：分别依据请求错误和成功响应的记录数量渲染。
- 跳转改变流程：只新增到现有页面的链接，不自动触发审核、发布或启用。
- UI 打磨掩盖真实异常：保留 `apiErrorMessage` 返回的真实原因，并提供重试。
- Runtime 受影响：使用独立 Worktree 和非标准端口验收，不重启正式服务。

## 验收

由代码差异、四页面状态测试、全量 Admin 测试、类型检查、生产构建、隔离浏览器回归和严格路径范围共同决定 Gate。

- Admin 全量：`29` 个测试文件、`75` 个测试全部通过。
- `pnpm typecheck`：通过。
- `pnpm build`：通过。
- 浏览器：隔离端口 `15177` 上四页面及跨页业务跳转通过，控制台 `0` 错误。
- 路径范围：所有变更均位于 `admin_web/**`。
- Runtime：正式服务未重启、未切换；隔离验收端口已释放。

Gate：`C_ADMIN_UX_POLISHED_V1`
