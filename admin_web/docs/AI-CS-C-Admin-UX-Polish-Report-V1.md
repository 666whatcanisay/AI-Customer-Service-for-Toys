# AI-CS C Admin UX Polish Report V1

## 1. 目标与边界

本轮基于 `C Admin Operational Workspace Optimization V1@f50ab0a`，只在 `admin_web/**` 内统一运营工作台、商品知识中心、导入中心和 AI 状态页面的状态表达、下一步入口和页面间业务跳转。

未修改 API、数据库、migration、contracts、R006、R009、A/RAG、Prompt、Runtime 或任何业务权限与状态流转。

## 2. 统一体验规则

新增通用展示组件 `OperationalStatePanel.vue`，四类状态统一回答：

1. **发生什么**：正在处理、暂无数据、读取失败或操作完成。
2. **为什么**：展示真实读取范围、缺失条件或 `apiErrorMessage` 返回的实际原因。
3. **下一步怎么办**：提供重试、返回工作台或进入现有处理页面的明确入口。

规则约束：

- 加载完成前不提前显示成功、空数据或 `0`。
- 空态只用于接口成功但无记录；失败态不伪装为空态。
- 成功态只显示真实返回结果。
- 所有入口只导航现有路由或重试现有读取，不自动触发审核、发布、启用或其他写操作。

## 3. 页面优化

### 运营工作台

- 加载时隐藏尚未返回的业务区，明确正在读取待办、生命周期、AI 和平台状态。
- 四项待办均为 `0` 时，显示“当前没有待处理事项”，同时说明该结论来自现有接口快照。
- 商品列表读取成功但为空时，显示“当前还没有商品生命周期数据”，引导进入商品管理。
- 商品生命周期或 AI 状态读取失败时，展示真实错误、重新读取和对应业务页面入口。
- 当前工作卡片统一增加“去处理 →”，快捷入口增加“立即前往 →”。
- 平台健康异常时明确引导到系统状态页面。

### 商品知识中心

- 页面加载、整体读取失败、无商品知识、店铺商品加载、店铺商品失败和筛选为空均使用统一状态结构。
- 商品上线成功或失败使用统一反馈：成功后检查客服/AI 状态，失败后核对操作人、勾选和当前状态。
- 商品状态文案统一为“资料：已审核/待审核/待补充”“客服：可用/未启用”“AI知识：未发布/发布中/已发布/同步失败/需重新同步”。
- 客服未启用商品增加“前往批量启用”锚点；资料未审核和 AI 未发布仍使用已有页面与按钮。
- 页面头部增加“返回运营工作台”，原批量启用、发布、详情和资料审核流程不变。

### 导入中心

- 可用店铺加载、读取失败、无店铺、未选择和已选择五种状态均明确原因与下一步。
- 失败态可重新读取；无店铺引导到店铺管理；选中店铺后明确引导到 R009 资料上传与审核。
- 六模板、六下载链接、四步引导和 Import Center 定位保持不变。
- 三个业务入口增加“继续上传审核 / 立即前往 / 查看处理建议”提示。
- 页面头部增加“返回运营工作台”。

### AI 状态

- 页面加载与整体读取失败使用统一状态面板；失败态同时提供重新读取和系统状态入口。
- 无已保存评测时明确“接口没有返回评测结果，不代表评测失败”，并链接现有评测记录。
- 知识质量中心和 AI 问题中心增加“立即前往 →”。
- 页面头部增加“返回运营工作台”；高级技术信息仍默认折叠。

## 4. 状态覆盖

| 页面 | 加载态 | 成功态 | 空态 | 失败态 |
| --- | --- | --- | --- | --- |

| AI 状态 | 读取 AI 状态 | 服务、知识、回答能力 | 无已保存评测 | AI 状态整体读取失败 |

## 7. 未解决问题

1. 浏览器回归使用正常运行的现有接口，因此加载、空和失败的全部组合由组件及页面单元测试覆盖，没有通过停止正式服务来制造浏览器故障。
2. 本轮只统一四个指定核心页面；其他 Admin 页面可在后续独立低风险任务中逐步复用统一状态组件。
3. 精确 collection 名称、服务版本、商品图片和今日趋势仍因现有接口未提供而不展示，本轮没有新增或推测数据。

## 8. 结论

四个 C Admin 核心页面已形成一致的状态语言和业务恢复路径。运营人员能从页面直接判断发生了什么、原因是什么、下一步应进入哪里，同时原有业务动作、接口和安全边界保持不变。
