# 本机启动与故障排查手册

## 正常启动与停止

在正式主仓库的 `scripts\windows\` 目录中使用以下入口：

| 目的 | 文件 |
| --- | --- |
| 本机启动 | `启动AI客服.bat` |
| 局域网客服入口启动 | `启动局域网客服.bat` |
| 本机状态检查 | `检查AI客服状态.bat` |
| 局域网状态检查 | `检查局域网客服状态.bat` |
| 安全停止 | `停止AI客服.bat` |
| 局域网只读诊断 | `诊断AI客服局域网.bat` |
| 防火墙检查/配置/删除 | `检查AI客服防火墙.bat`、`配置AI客服防火墙.bat`、`删除AI客服防火墙规则.bat` |
| 打开运营后台 | `打开运营后台.bat` |

正式启动顺序是 C（平台 8011）→ A（AI/RAG 8000）→ B（客服工作台 5173）→ Admin（运营中心 5174）。启动过程会执行数据库迁移、测试数据包重复导入保护、受控知识同步和真实 Ollama smoke；其中任一步失败，都应按输出原因处理，而不是手工补起某一个服务掩盖错误。

本机入口通常是 B `http://127.0.0.1:5173/` 与 Admin `http://127.0.0.1:5174/`。局域网模式的外部客服入口只应为选定物理网卡上的 `5173`；A、C 和 Admin 保持服务器本机访问。前端通过固定同源代理访问 A/C，不要求客户端开放或访问 8000、8011。

## 配置检查

本机私有配置文件为 `scripts\windows\config.local.ps1`，必须被 Git 忽略。它应指向正式主仓库的 `backend\.venv` 和 `platform_backend\.venv`，并包含正确的端口、绑定地址、测试数据 ZIP 路径和允许来源。不要提交这个文件、备份文件、密钥、数据库、日志或运行记录。

局域网模式可使用 `LanAddress = 'auto'`；每次启动重新选择具备 IPv4、默认网关且状态为 Up 的物理网卡，优先以太网、其次 WLAN，并排除 Loopback、WSL、Hyper-V、Bluetooth、VPN/TUN、`198.18.0.0/15` 和 `169.254.0.0/16`。多个有效物理网卡无法判定时，应停止并配置首选网卡名。

## 常见问题

| 现象 | 先检查什么 | 安全处理 |
| --- | --- | --- |
| `ERR_CONNECTION_REFUSED` | 运行状态脚本、端口监听、日志 | 使用正式启动脚本；不要按端口结束未知进程 |
| 404 | 实际 URL、服务工作目录、运行 SHA 与路由 | 确认运行的是正式仓库对应版本，检查代理前缀 |
| CORS | 浏览器入口、`CORS_ALLOWED_ORIGINS`、是否绕过 5173 直连 | 客户端使用 5173；不要为方便而暴露 A/C |
| 端口被占用 | 状态脚本输出的 PID、命令、路径、父子关系 | 只有身份验证通过的受管项目进程可停止 |
| A/C `.venv` 缺失 | `config.local.ps1` 的 Python 路径 | 在正式仓库按项目说明准备虚拟环境，不能复制未知 Python |
| `node_modules` 缺失 | 前端或 Admin 的依赖安装状态 | 在对应目录安装锁定依赖；不要提交依赖目录 |
| Ollama 或模型不可用 | 本机 Ollama 服务、`qwen3.5:9b`、A `/api/status` | 修复模型后重新使用完整启动流程，不能用伪回答替代 |
| 测试数据未导入 | C 健康、数据包原始 ZIP、导入历史 | 使用经校验的原始 ZIP；不要重压、篡改或提交数据包 |
| 笔记本无法访问 | 客户端 `Test-NetConnection <服务器IP> -Port 5173`、路由、Private 防火墙规则 | 只在受控 Private 子网开放 TCP 5173；不关闭防火墙、不开放 8000/8011/5174 |

日志在 `.runtime\logs`；局域网诊断报告写入被忽略的 `.runtime\diagnostics`。二者都不能提交。

## 必须避免的操作

- 不关闭 Windows 防火墙，不修改 VPN 配置。
- 不执行 `taskkill /IM python.exe`、不按端口批量结束、不强杀未知进程。
- 不停止 Ollama，不删除虚拟环境、`node_modules`、原始测试 ZIP、数据库或向量库。
- 不通过浏览器直连内部 8000/8011 作为常规客服方案。
