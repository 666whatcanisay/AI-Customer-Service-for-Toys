# C-T02B 测试数据包与冻结只读接口

## 固定测试边界

- 版本：`V0.3.1`，schema：`0.3.1-test`。
- 租户/平台/店铺：`TENANT-PDD-SM-TEST / pdd / PDD-SM`。
- 必须为 `test_data_mode=true`、`production_usable=false`、`response_mode=SUGGESTION_ONLY`、`allow_auto_send=false`。
- 只进入 `test_*` 隔离表；不进入正式租户、审核、发布、RAG/Chroma 或自动发送。

## ZIP 入口

- `POST /api/v1/test-data-packages/preflight`：只读预检，无数据库 Session。
- `POST /api/v1/test-data-packages`：重复全部安全/manifest/工作簿校验后单事务导入。
- `GET /api/v1/test-data-packages`：管理端使用的 `{items,total}` 测试包列表。

## ZIP 布局与逻辑根目录

- 布局一：`manifest.json` 在物理 ZIP 根目录，文件路径直接作为逻辑路径。
- 布局二：所有文件位于同一个安全外层目录，且该目录的直接子项包含 `manifest.json`；解析器只在内存中去掉这一层公共前缀，不解压、不重写上传字节，原始 ZIP SHA-256 仍按上传内容计算。
- 物理条目必须先通过既有数量、总解压大小、单文件大小、路径穿越、符号链接和重复路径检查。随后拒绝根/外层双 manifest、多顶层目录、两层及以上包装、逻辑路径重复、以及 manifest 使用外层物理路径引用文件。
- `manifest.files`、`workbooks` 和工作簿证据 `relative_path` 必须全部使用逻辑根目录相对路径，不能包含外层目录名。

## 五个冻结 GET

目录接口统一返回 `{items:[...], total:number}`。

`GET /api/v1/test-catalog/stores` item：

`tenant_id, platform, store_code, store_name, trial_enabled, knowledge_scope, response_mode, allow_auto_send, test_data_mode, production_usable`。

`GET /api/v1/test-catalog/products?store_code=` item：

`product_id, platform, store_code, product_name_official, product_name_display, sales_status, age_min, age_max, safety_summary, review_status, publishable`。

`GET /api/v1/test-catalog/products/{product_id}/skus` item：

`sku_id, product_id, sku_code, sku_name_official, sku_name_display, relation_type, canonical_sku_id, reference_sku_id, component_sku_refs, publishable`。`component_sku_refs` 固定为 `string[]`。

`GET /api/v1/test-knowledge-packages/{package_id}/rag-export` 包级字段：

`package_id, version, schema_version, tenant_id, platform, store_code, test_data_mode, production_usable, response_mode, allow_auto_send, items, total`。

items 固定为：

`knowledge_id, knowledge_type, tenant_id, platform, store_code, product_id, sku_id, title, content, answer_action, risk_level, source_ids, test_data_mode, production_usable`。

`source_ids` 为 `string[]`；`knowledge_type` 仅为 `PRODUCT_FACT|SKU_FACT|FAQ|SAFETY_RULE`；`answer_action` 仅为 `DIRECT_ANSWER|CONTROLLED_ANSWER|ASK_CLARIFY|REQUIRE_LOOKUP|TRANSFER_HUMAN|REFUSE`。

`GET /api/v1/test-knowledge-packages/{package_id}/evaluations` 使用相同包级字段，item 固定为：

`case_id, case_type, platform, store_code, product_id, sku_id, customer_question, conversation_context, expected_action, expected_key_facts, forbidden_claims, expected_source_ids, expected_required_fields, risk_level, pass_criteria, expected_response_mode, allow_auto_send_expected`。

`expected_key_facts/forbidden_claims/expected_source_ids/expected_required_fields` 固定为 `string[]`，空值返回 `[]`。

## 兼容与错误

错误沿用 `{error:{code,message,details?},request_id}`。本约定未写入 `contracts/**`，没有修改 A/B 业务代码或新增 chat endpoint；C 是五个 GET 的权威提供方，但当前只完成 C 线本地数据库/API 验证，不宣称 A/B 真实联调通过。

附件只保存相对路径、SHA-256 和元数据；任何接口都不得返回图片二进制或原始 RTF。
