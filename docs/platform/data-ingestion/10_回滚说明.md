# 回滚说明

回滚 C-T02 时应保留 C-T01 健康骨架，并按提交逆序使用 `git revert <sha>` 创建可审计回滚提交，不使用 `reset --hard`。数据库先备份（若存在允许保留的本地演示数据），再在 `platform_backend` 执行：

```powershell
.\.venv\Scripts\python.exe -m alembic downgrade base
```

然后逆序 revert 文档、测试、管理端和后端 C-T02 提交。确认 `/health` 和 `/system-status` 仍通过，检查 `git diff --check` 和 `git status --short`。

本轮没有正式发布、A 线写入、上传文件持久化或外部系统副作用，因此无需执行知识撤回或外部数据补偿。若只回滚某个失败批次，可在本地数据库中按明确批次 ID 处理，但 C-T02 没有提供删除 API，禁止对 READY_FOR_REVIEW 做未审计删除。
