# 安全边界

- 只接受 `.xlsx` 和明确 OOXML MIME；上传上限默认 5 MB，数据行上限默认 1000，解压内容上限 50 MB。
- 使用 `PurePosixPath(...).name` 仅保留安全 basename；工作簿不落盘、不执行公式或宏，解析后由请求生命周期释放。
- 禁止隐藏数据表、外部链接保留与公式可信化；不支持 `.xlsm` 或任意压缩包。
- 文件生成 SHA-256；数据库只保存批次元数据、原始/规范行 JSON、错误和待审核记录，不保存上传文件。
- 原始区（`ImportRow.raw_data_json`）、规范/校验区（`normalized_data_json`/issues）和待审核区（`StagedProductSku`）逻辑分离；没有试用区或正式区写入。
- 应用不记录完整行内容；仓库禁止 `.env`、数据库、上传件、日志、依赖、构建产物、Token、客户数据和真实知识资料。
- 当前没有认证、授权、审计持久化、保留/删除策略或生产级恶意文件扫描，因此只能用于受控本地演示，不能宣称生产安全就绪。
- C-T02A 预检在内存中读取同一上传字节并返回摘要；路由不注入数据库 Session，不保存工作簿、原始行或预检结果。正式导入会再次执行同一安全与校验规则，不能把预检结果当作绕过校验的凭证。

C-T02 未接金蝶，未保存任何金蝶账号、密码或 Token；未调用 A 线、RAG、Chroma、Embedding 或模型。

## C-T02B ZIP 测试区

- 只接受 `.zip` 与 ZIP MIME/签名，默认压缩包 32 MB、100 个文件、展开后 64 MB、单文件 20 MB；拒绝路径穿越、反斜杠路径、绝对路径、重复路径、符号链接、加密项和异常压缩比。
- 物理 ZIP 条目先完成路径、符号链接、加密、重复、数量、单文件大小和总展开大小检查；随后仅接受根目录 `manifest.json`，或唯一一层安全外层目录内的 `manifest.json`。布局二只在内存中剥离公共前缀，原始上传字节和 SHA-256 不变。
- 逻辑根目录的文件集必须与 manifest 一致，逐文件大小和 SHA-256 全部复算；拒绝根目录与外层双 manifest、多顶层目录、两层包装、逻辑路径重复以及 manifest 引用外层目录之外的文件；只接受 V0.3.1/0.3.1-test。
- 强制固定 `TENANT-PDD-SM-TEST/pdd/PDD-SM` 与 `test_data_mode=true`、`production_usable=false`、`SUGGESTION_ONLY`、`allow_auto_send=false`；任一不符即拒绝且不写数据库。
- 00～08 工作表必须名称、顺序、表头、数量、来源引用、REFERENCE/BUNDLE 关系和响应动作全部通过后，才单事务写入 `test_*` 表。
- 附件与原始 RTF 只验证 ZIP 内字节；数据库只保存相对路径、SHA 和元数据，不保存二进制。五个只读接口不返回附件或 RTF 内容。
- 测试区与 C-T02 `ImportBatch/ImportRow/StagedProductSku` 分离，不进入正式租户、审核或发布状态机。
