# AI response feedback v1 interface supplement

## Scope and compatibility

This C-owned implementation supplements the frozen `ai-feedback.v1-draft` interface for the blocked A analysis flow. It is additive to all existing C-T05 and MVP-PLUS-01 paths. `contracts/**` remains version `0.1.0` and is not changed by this work.

Only the following cross-line interfaces are provided by C:

- `GET /api/v1/admin/ai-quality/feedback-cases` (C to A, read-only)
- `POST /api/v1/admin/ai-quality/analysis-results` (A to C, evidence storage only)

`POST /api/v1/admin/ai-response-feedback/{feedback_id}/confirm` is a C-internal human-confirmation control. It is not an A or B integration endpoint. It is the only v1 operation that changes `NEW` to `ANALYZING` and creates the controlled export snapshot.

No A model is called by C. C does not change a Prompt, publish knowledge, train a model, send a customer message, change an order, or write to ERP.

## Feedback types and eligibility

The closed v1 enum is shared in C storage, A exports, filters, tests, and analysis evidence:

| Value | Meaning |
| --- | --- |
| `FACT_ERROR` | The answer conflicts with confirmed facts. |
| `MISSING_INFO` | The answer omits information needed for the question. |
| `STYLE_ISSUE` | The answer is unsuitable or unclear for customer service. |
| `RISK_ISSUE` | The answer creates safety, compliance, promise, or communication risk. |
| `OTHER` | A human-specified reason outside the four categories. |

An `AIResponseFeedback` record starts as `NEW`. A C operator must manually confirm that the content is de-identified and suitable for test analysis. C then atomically writes `status=ANALYZING` and `analysis_status=ANALYZING`. Only this state is exported to A. A successful accepted writeback atomically changes both fields to `ANALYZED`; analyzed records are not exported again in v1.

## C to A: versioned feedback cases

`GET /api/v1/admin/ai-quality/feedback-cases?cursor={optional}&size={optional}` returns only manually confirmed `ANALYZING` snapshots. It is read-only and does not reserve, claim, enqueue, or change a record.

```json
{
  "items": [
    {
      "feedback_id": "ARF-20260725-000001",
      "revision": 1,
      "question": "What age is this toy suitable for?",
      "ai_answer": "It is suitable for children aged six to twelve.",
      "final_answer": "It is for ages six to twelve with adult supervision and not for children under three.",
      "feedback_type": "MISSING_INFO",
      "content_hash": "sha256:3b5f3bbf2bca5c8dc57ef5a0d394452f4f9b8ba56b7f77fb155dc5622990c059",
      "created_at": "2026-07-25T08:00:00Z"
    }
  ],
  "next_cursor": null
}
```

The cursor is the last returned `feedback_id`; order is ascending by that identifier. The response intentionally excludes store/SKU context, creator identity, feedback note, confirmation actor/reason, raw chat context, browser data, source data, prompt text, model inputs, logs, and internal audit metadata.

## A to C: analysis evidence writeback

`POST /api/v1/admin/ai-quality/analysis-results` accepts analysis evidence for one exported revision. It does not invoke or configure an AI model; A remains responsible for its explicit model invocation before this request.

```json
{
  "feedback_id": "ARF-20260725-000001",
  "revision": 1,
  "analysis_run_id": "AQR-20260725-000001",
  "model_version": "qwen3.5:9b",
  "prompt_version": "ai-quality-feedback-v1",
  "analysis": {
    "summary": "The answer omitted the lower-age restriction.",
    "analysis_outcome": "NEEDS_REVIEW"
  },
  "suggestions": [
    {
      "category": "PROMPT_HYPOTHESIS",
      "description": "Check lower-age restrictions together with the age range.",
      "evidence_summary": "The confirmed final answer contains the omitted restriction."
    }
  ]
}
```

A successful first write returns HTTP `201`:

```json
{
  "feedback_id": "ARF-20260725-000001",
  "revision": 1,
  "status": "ANALYZED",
  "analysis_status": "ANALYZED",
  "analysis_run_id": "AQR-20260725-000001",
  "model_version": "qwen3.5:9b",
  "prompt_version": "ai-quality-feedback-v1",
  "analysis": {
    "summary": "The answer omitted the lower-age restriction.",
    "analysis_outcome": "NEEDS_REVIEW"
  },
  "suggestions": [
    {
      "category": "PROMPT_HYPOTHESIS",
      "description": "Check lower-age restrictions together with the age range.",
      "evidence_summary": "The confirmed final answer contains the omitted restriction."
    }
  ],
  "recorded_at": "2026-07-25T08:05:00Z"
}
```

`analysis` must be a non-empty JSON object and `suggestions` must be a JSON array. Their internal vocabulary is evidence supplied by A; C stores it for human review and never treats it as an instruction to modify a Prompt, model, knowledge base, customer response, order, or ERP record.

## Revision and content-hash rules

- C assigns `revision=1` for the v1 record. No content-overwrite, reclassification, or revision-bump API is exposed in this task.
- On C human confirmation, the record content becomes immutable for v1 and C computes `content_hash` once.
- `content_hash` is `sha256:` followed by SHA-256 over canonical UTF-8 JSON (sorted keys, compact separators) of `feedback_id`, `revision`, `store_code`, `product_id`, `sku_id`, `question`, `ai_answer`, `final_answer`, `feedback_type`, and `feedback_note`.
- A records the `feedback_id`, `revision`, and exported `content_hash` with its own analysis evidence. The writeback schema requires the first two so C rejects stale revisions; C copies the controlled hash into its stored evidence. The hash identifies the exported immutable content and is not accepted as a client-controlled replacement value.
- Any future content amendment, alternate revision, re-analysis, or hash-input change requires a separately frozen versioned contract. It must not overwrite an analyzed v1 record.

## Idempotency and errors

The idempotency key is `analysis_run_id` within C:

- The first valid writeback for an exportable `feedback_id + revision` stores one analysis record and returns HTTP `201`.
- A retry with the same `analysis_run_id` and structurally equivalent payload fields (`feedback_id`, versions, `analysis`, and `suggestions`) returns the stored response with HTTP `200`; no second evidence record is created.
- Reuse of an existing `analysis_run_id` with any different record or payload, a second successful analysis for the same feedback revision, or a concurrent uniqueness collision returns HTTP `409` with `AI_RESPONSE_FEEDBACK_ANALYSIS_CONFLICT`.

| HTTP | Code | Meaning |
| --- | --- | --- |
| 404 | `AI_RESPONSE_FEEDBACK_NOT_FOUND` | `feedback_id` does not exist in C. |
| 409 | `AI_RESPONSE_FEEDBACK_INVALID_STATUS_TRANSITION` | A non-`NEW` record was submitted to C internal confirmation. |
| 409 | `AI_RESPONSE_FEEDBACK_NOT_EXPORTABLE` | The feedback has not been confirmed or is no longer `ANALYZING`. |
| 409 | `AI_RESPONSE_FEEDBACK_REVISION_MISMATCH` | The writeback revision is not the controlled C revision. |
| 409 | `AI_RESPONSE_FEEDBACK_ANALYSIS_CONFLICT` | A completed analysis or `analysis_run_id` conflicts with the writeback. |
| 422 | `AI_RESPONSE_FEEDBACK_VALIDATION_FAILED` | Required fields, IDs, or pagination are invalid. |
| 422 | `AI_RESPONSE_FEEDBACK_ANALYSIS_OUTPUT_INVALID` | `analysis` or `suggestions` is not the required JSON object/array shape. |

## Privacy and audit boundary

This is synthetic/de-identified test-operation support only. C records human confirmation actor, time, reason, redaction reminder version, immutable hash, and successful analysis metadata in its controlled database, but those governance fields are not included in the A export. The implementation does not log feedback content.

`v1-reminder-only` is a submission/confirmation reminder, not automatic redaction, authentication, authorization, retention, access auditing, or a production security claim. Real customer data, raw conversations, attachments, customer identity, order data, browser state, source documents, credentials, and logs remain out of scope.
