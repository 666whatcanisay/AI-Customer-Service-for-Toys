# AI response feedback v1 provider contract

## Status and boundary

This document records the C Provider implementation of frozen `ai-feedback.v1`. It is an additive C-owned implementation: `contracts/**` remains version `0.1.0`, and no B frontend, A backend, Prompt, knowledge, model, customer, order, or ERP behavior is changed.

The only cross-line API paths are:

- `POST /api/v1/ai-response-feedback` (B to C)
- `GET /api/v1/ai-response-feedback` (C to B)
- `GET /api/v1/admin/ai-quality/badcases` (C to A)
- `POST /api/v1/admin/ai-quality/analysis-results` (A to C)

`/api/v1/admin/ai-quality/feedback-cases` is not provided and must not be consumed. C internal `POST /api/v1/admin/ai-response-feedback/{feedback_id}/confirm` is the human-confirmation control, not an A/B integration endpoint.

## Closed feedback-type enum

| Value | Meaning |
| --- | --- |
| `FACT_ERROR` | Answer conflicts with confirmed facts. |
| `MISSING_INFO` | Answer omits information needed for the question. |
| `STYLE_ISSUE` | Answer is unsuitable or unclear for customer service. |
| `RISK_ISSUE` | Answer creates safety, compliance, promise, or communication risk. |
| `OTHER` | Human-specified reason outside the four categories; `feedback_note` is required. |

No alias, mapping, default, or hidden additional value is permitted in v1.

## B submission and history

### Create

`POST /api/v1/ai-response-feedback` requires a non-blank `Idempotency-Key` header for every explicit B submission.

For an allowed B browser origin, CORS explicitly permits this header for the
feedback preflight. The policy remains an explicit header allowlist; it does
not use a wildcard.

```http
Idempotency-Key: 4da1d1ef-94f2-4b87-8075-f4e795cec9e1
```

```json
{
  "store_code": "PDD-SM",
  "product_id": "PROD-001",
  "sku_id": "SKU-001",
  "question": "What age is this toy suitable for?",
  "ai_answer": "It is suitable for children aged six to twelve.",
  "feedback_type": "MISSING_INFO",
  "feedback_note": null,
  "final_answer": "It is for ages six to twelve with adult supervision and not for children under three.",
  "created_by": "TESTER-001",
  "context": {
    "store_code": "PDD-SM",
    "product_id": "PROD-001",
    "sku_id": "SKU-001"
  }
}
```

`context` allows only `store_code`, `product_id`, and `sku_id`; all three values must equal the top-level fields. Raw chat context, source text, order/customer identity, browser state, paths, credentials, logs, and unknown keys are rejected. Client-supplied `feedback_id`, `status`, `analysis_status`, and `created_at` are rejected.

C generates the identifier and forces both lifecycle fields to `NEW`. The B receipt is:

```json
{
  "feedback_id": "ARF-20260725-000001",
  "status": "NEW"
}
```

Idempotency is scoped by `POST`, `/api/v1/ai-response-feedback`, `created_by`, and `Idempotency-Key`.

- The same scope and normalized payload replay the original `201` receipt and do not create another record.
- The same scope with a different normalized payload returns `409 AI_RESPONSE_FEEDBACK_IDEMPOTENCY_CONFLICT`.
- A new explicit submission uses a new key. UI disabled states do not replace this server-side rule.

### History

`GET /api/v1/ai-response-feedback?created_by={required}&feedback_type={optional}&status={optional}&page={optional}&size={optional}` returns only B's minimum status projection.

```json
{
  "items": [
    {
      "feedback_id": "ARF-20260725-000001",
      "revision": 1,
      "store_code": "PDD-SM",
      "product_id": "PROD-001",
      "sku_id": "SKU-001",
      "feedback_type": "MISSING_INFO",
      "status": "ANALYZED",
      "analysis_status": "ANALYZED",
      "created_at": "2026-07-25T08:00:00Z"
    }
  ],
  "total": 1,
  "page": 1,
  "size": 20
}
```

It never returns confirmation actor/reason, A analysis/suggestions, prompt/model data, raw source data, or another operator's records. `created_by` is a test filter only, not authentication or authorization.

## Controlled C to A export

`GET /api/v1/admin/ai-quality/badcases?cursor={optional}&size={optional}` returns only C-human-confirmed records in `ANALYZING`. It is read-only: it does not claim a case, invoke a model, or change status.

```json
{
  "items": [
    {
      "feedback_id": "ARF-20260725-000001",
      "revision": 1,
      "store_code": "PDD-SM",
      "product_id": "PROD-001",
      "sku_id": "SKU-001",
      "question": "What age is this toy suitable for?",
      "ai_answer": "It is suitable for children aged six to twelve.",
      "final_answer": "It is for ages six to twelve with adult supervision and not for children under three.",
      "feedback_type": "MISSING_INFO",
      "feedback_note": null,
      "context": {
        "store_code": "PDD-SM",
        "product_id": "PROD-001",
        "sku_id": "SKU-001"
      },
      "content_hash": "sha256:...",
      "redaction_version": "v1-reminder-only"
    }
  ],
  "next_cursor": null
}
```

`NEW` and `ANALYZED` records are never exported. C records the confirmation actor, time, reason, and redaction reminder version internally; A receives only the frozen analysis snapshot.

## A writeback and snapshot matching

`POST /api/v1/admin/ai-quality/analysis-results` stores analysis evidence only. C does not invoke a model and does not execute a suggestion.

```json
{
  "feedback_id": "ARF-20260725-000001",
  "revision": 1,
  "content_hash": "sha256:...",
  "feedback_type": "MISSING_INFO",
  "analysis_run_id": "AQR-20260725-000001",
  "model_version": "qwen3.5:9b",
  "prompt_version": "ai-quality-feedback-v1",
  "analysis": {
    "summary": "The answer omitted the lower-age restriction.",
    "analysis_outcome": "NEEDS_REVIEW"
  },
  "suggestions": [
    {
      "category": "PROMPT_HYPOTHESIS",
      "description": "Check lower-age restrictions with the age range.",
      "evidence_summary": "The confirmed final answer contains the omitted restriction."
    }
  ]
}
```

C requires the current record to be `ANALYZING` and validates all of `feedback_id`, `revision`, `content_hash`, and `feedback_type` against its immutable snapshot before changing both status fields to `ANALYZED`.

- First valid write: `201` and one stored evidence record.
- Same `analysis_run_id` with the same complete payload: `200` and the original stored result.
- Same run ID with different evidence, or any second successful analysis for the snapshot: `409 AI_RESPONSE_FEEDBACK_ANALYSIS_CONFLICT`.
- Different `revision` or `content_hash`: `409 AI_RESPONSE_FEEDBACK_EXPORT_SNAPSHOT_MISMATCH`.
- Different `feedback_type`: `409 AI_RESPONSE_FEEDBACK_TYPE_MISMATCH`.

## C internal Admin analysis-result view

`GET /api/v1/admin/ai-quality/analysis-results` is a C-owned, read-only projection for the internal Admin AI optimization pool. It is not a B/A frozen `ai-feedback.v1` consumer path and does not alter the B history, A `/badcases` export, or A writeback request/response protocol.

It returns only feedback for which C has already stored one successful A evidence record and both lifecycle fields are `ANALYZED`. `NEW` and `ANALYZING` feedback is deliberately absent. The endpoint has no query parameters and never changes feedback, analysis, Prompt, knowledge, customer, order, or ERP state.

```json
{
  "items": [
    {
      "feedback_id": "ARF-20260725-000001",
      "revision": 1,
      "content_hash": "sha256:...",
      "feedback_type": "MISSING_INFO",
      "analysis_run_id": "AQR-20260725-000001",
      "analysis_status": "ANALYZED",
      "model_version": "qwen3.5:9b",
      "prompt_version": "ai-quality-feedback-v1",
      "analysis": { "summary": "The answer omitted the lower-age restriction." },
      "suggestions": [{ "category": "PROMPT_HYPOTHESIS" }],
      "created_at": "2026-07-27T08:00:00Z",
      "question": "What age is this toy suitable for?",
      "ai_answer": "It is suitable for children aged six to twelve.",
      "final_answer": "It is for ages six to twelve with adult supervision and not for children under three."
    }
  ],
  "total": 1
}
```

`created_at` is the persisted evidence-record time. The question, AI answer, and final answer are returned only so this same internal Admin view can display the evidence context; no additional detail or write endpoint is introduced.

The `/admin/` namespace is the current test-portal boundary. Formal authentication, authorization, sensitive-view audit records, retention, and automatic redaction are not implemented and must not be inferred from this route or UI.

## Revision, hash, and privacy rules

C initializes v1 records at `revision=1`. Human confirmation freezes the record; v1 exposes no overwrite, reclassification, delete, revision-bump, or re-analysis endpoint. The frozen `content_hash` is `sha256:` plus SHA-256 over canonical UTF-8 JSON (sorted keys and compact separators) of `feedback_id`, `revision`, `store_code`, `product_id`, `sku_id`, `question`, `ai_answer`, `final_answer`, `feedback_type`, and `feedback_note`.

`v1-reminder-only` is a reminder, not automatic redaction, authentication, authorization, retention, or a production audit/security claim. Only synthetic or already de-identified test content belongs in this flow. C does not log feedback text or store raw chat attachments, credentials, or customer/order identity.
