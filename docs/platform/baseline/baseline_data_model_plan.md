# 数据模型与生命周期设计（未实现）

本文只冻结后续设计约束，不创建表、ORM 或迁移。

## 知识状态机

目标状态集合：

```text
DRAFT
→ CLEANED
→ REVIEW_PENDING
→ REVIEW_APPROVED / REVIEW_REJECTED
→ TRIAL_PUBLISHED
→ FORMAL_PUBLISHED
→ EXPIRED / DEACTIVATED
→ SUPERSEDED
```

分支语义：`REVIEW_REJECTED` 不得进入发布状态，只能通过新版本回到编辑/清洗流程；`REVIEW_APPROVED` 才可进入试用发布。试用知识通过额外发布校验后才可正式发布。

## 强制约束

- 所有未列入允许表的状态跳转必须拒绝，并留下可追溯原因。
- 未审核、无来源、最终话术为空、风险未确认或已过期的知识不得正式发布。
- 发布到 RAG 失败必须记录为失败，不能写成试用或正式发布成功。
- 优秀案例只能形成候选，不得自动审核或自动发布。
- 旧版本不得覆盖；替代关系必须可追溯到前后版本。

## 数据分区

- 原始区：加密保存最小必要原始材料，禁止模型直接读取。
- 脱敏区：清洗和脱敏副本，供后续治理任务使用。
- 治理区：结构化事实、版本、审核决定和来源证明。
- 试用区：已审核但仅获试用许可的发布版本。
- 正式区：完成正式发布校验的版本。

五个区域必须逻辑隔离；私有仓库本身不构成隐私保护。
