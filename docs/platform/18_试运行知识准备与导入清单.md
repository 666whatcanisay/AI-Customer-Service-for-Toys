# 试运行知识准备与导入清单

适用对象：负责维护商品资料的运营同事。本文只说明内部试运行环境的资料准备与商品/SKU 导入，不构成生产发布流程。

## 先确认边界

- 商品/SKU Excel 导入只接收可核对的商品事实，导入后进入待审核区。
- 导入不等于知识发布：不会自动写入 AI 知识、修改提示词、发送客户消息或写入 ERP。
- 不确定的事实不要猜测；保留来源，待补齐后再提交。
- 不要提交客户聊天记录、订单信息、手机号、地址或其他个人信息。

## 准备资料

1. 在运营后台的“数据导入”页面下载标准 Excel 模板。
2. 只编辑“商品SKU资料”工作表，从第 3 行开始填资料；不要更改工作表名、表头、字段顺序或隐藏工作表。
3. 每一行至少确认：租户、平台、店铺编码、商品名称、SKU 名称、来源名称，以及商品和 SKU 的一个可追溯标识。
4. 年龄、材质、包装内容、规格等字段必须来自已经核实的来源；无法确认时留空并保留来源说明。
5. 仅上传 `.xlsx` 文件。系统不接收 CSV、PDF、Word、截图、压缩包或带宏的工作簿。

## 导入前完整性检查

在点击正式导入前，先执行页面中的“先预检”：

- 缺失列：回到模板补齐，不能直接上传。
- 格式错误：检查日期、平台枚举、年龄和唯一标识。
- 重复行：确认是否应保留一条最新版资料，避免重复提交。
- 冲突行：核对来源后再决定，不能以导入覆盖的方式解决。
- 公式、隐藏工作表或宏：系统不会执行，也不能作为导入事实来源。

预检通过仅表示格式和基本完整性合格；不表示资料已发布给 AI。

## 其他知识资料

FAQ、安全规则和来源证据不通过商品/SKU Excel 入口导入。当前测试基线使用经过 Manifest 校验的受控测试 ZIP；后续正式资料需单独走版本化审核流程。不要将零散文件混入商品/SKU 模板，也不要将优秀客服案例自动提升为知识。

## 导入后核对

1. 在“导入批次”查看结果和错误报告。
2. 在“商品与 SKU”核对显示的数据是否与来源一致。
3. 在“常见问题”“安全规则”“知识来源”确认相关受控资料是否存在。
4. 发现事实冲突时，在“数据冲突”中记录并人工处理；不要用 AI 回答或客服案例覆盖源资料。
