# 商品资料与知识质量闭环（TARGET MODE V2）

## 目的与边界

本模块让运营把**已去标识化的商品资料**以受控方式上传、人工审核，再交由 A 生成可追溯的质量分析证据。运营根据缺口补充资料时，必须上传一个新 revision；系统不会覆盖已审核版本。

闭环为：

```text
运营上传资料 → C 受控识别 → 人工审核 → A 读取已审核快照
→ A 回写分析证据 → C 展示质量缺口 → 运营上传修订版 → 客服查看简要状态
```

本模块不发布知识到 RAG、不训练模型、不修改 Prompt、不自动回复客户，也不修改订单、ERP、退款或售后数据。客服端只可读取简短的资料就绪提示，不能读取原始文件、分析正文或技术路径。

冻结的跨线协议是 `docs/control/interfaces/knowledge-quality-loop.v1.md`。本实现没有修改该文档或 `contracts/**`。

## C 端数据与状态

`KnowledgeMaterial` 以 `(material_id, revision)` 唯一标识一个不可变资料版本。首次上传生成 `KMT-*` 和 revision `1`；修订时带原 `material_id` 并生成下一个 revision。资料的业务范围（店铺、商品、SKU、类型、提交人）不能借修订改变。

状态流转如下：

```text
RECEIVED → RECOGNIZED → REVIEWING → APPROVED_FOR_ANALYSIS → ANALYZING → ANALYZED
                              └────────────────────────────→ REJECTED
```

当前识别完成后直接显示 `RECOGNIZED`；`RECEIVED` 和 `REVIEWING` 保留给后续异步识别或人工审核过程。只有 `APPROVED_FOR_ANALYSIS` 的固定快照可导出给 A。A 的结果写回后创建不可变 `KnowledgeQualityAssessment`，其 `assessment_id`、`analysis_run_id`、模型版本、Prompt 版本、`content_hash` 和所有缺口一起保存。

缺口由 C 生成 `gap_id` 并初始为 `OPEN`，A 不能在写回时指定缺口状态，也不能修改资料状态、Prompt 或知识发布状态。

## 运营使用说明

1. 在 5174 的“中文资料模板”下载统一 Excel；先阅读“填写说明”和“字段说明”，只填写已核实的商品资料，不填写客户聊天、手机号、地址、订单或支付信息。
2. 上传 `.txt`、`.md`、`.csv`、`.json` 或 `.xlsx` 文件（默认最多 5 MB），选择店铺、商品、SKU、资料类型并填写资料名称和提交人。
3. 先看“识别结果”：系统只显示可读性、已识别字段和缺少字段。遇到不支持格式、空文件、过大文件或疑似手机号/身份证号时，页面显示原因；系统不做自动脱敏。
4. 人工确认资料来源、事实和去标识化后，选择“通过并交给 AI 分析”；不通过则拒绝并记录说明。
5. 在“AI 管理 → 资料质量与补充”查看中文摘要和缺口。按缺口修订资料后，回到上传页并提交为新 revision；不要覆盖或修改旧版本。

## C Provider 接口

| 用途 | 路径 | 访问边界 |
| --- | --- | --- |
| 受控上传 | `POST /api/v1/admin/knowledge-materials` | multipart；必须有 `Idempotency-Key`；原始文件仅写入受忽略运行目录 |
| 运营列表/详情 | `GET /api/v1/admin/knowledge-materials`、`GET /api/v1/admin/knowledge-materials/{material_id}` | C Admin；详情只有限长文字预览，不返回原始二进制或存储路径 |
| 人工审核 | `POST /api/v1/admin/knowledge-materials/{material_id}/review` | 只能审核当前 `RECOGNIZED` revision |
| A 读取 | `GET /api/v1/admin/knowledge-quality/analysis-inputs` | 仅 `APPROVED_FOR_ANALYSIS` 的快照；带 revision/hash |
| A 回写 | `POST /api/v1/admin/knowledge-quality/analysis-results` | 严格校验 material/revision/hash；相同完整 `analysis_run_id` 幂等回放为 200 |
| C 质量池 | `GET /api/v1/admin/knowledge-quality/assessments` | C Admin 只读结果投影 |
| 客服简要状态 | `GET /api/v1/customer-knowledge-status` | 只返回中文状态与摘要，不返回资料内容 |

`analysis_run_id` 对应不同内容会冲突；同一资料 revision 只能有一份分析证据。资料分析结果不会自动改变任何 RAG、模型或客服行为。

## 资料保护与保留

原始上传字节仅保存在 `PLATFORM_KNOWLEDGE_MATERIAL_STORAGE_DIR`（默认 `platform_backend/.runtime/knowledge-materials`）下。该目录被 Git 忽略；接口、列表、日志和客服状态不暴露该路径或原始二进制。运营仍需在上传前人工去标识化：本版本仅做手机号和身份证号的提示性拦截，不具有完整的自动脱敏、权限、审计或保留期限能力。

## 验证与交接

本 C 端变更的验证覆盖上传幂等、受控文件保存、原始路径隐藏、审核、仅审核通过的导出、revision/hash 校验、A 结果幂等写回、C 生成缺口治理字段、新 revision 纠正、疑似敏感标识拦截和客服端紧凑投影。A 的真实模型调用与 B 的客服呈现由各自线路在集成阶段验证。
