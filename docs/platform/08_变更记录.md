## 2026-07-27 - C-OPERATION-V1.1 daily AI operations center

- Added the C-internal, read-only `GET /api/v1/admin/operations/today` aggregation and its Admin UI client. It combines a single UTC-day, content-free operating snapshot with the landing page's independent platform-health and A-module service probes.

## 2026-07-27 - P0 customer-efficiency Provider

- Added content-free `CustomerEfficiencyEvent` persistence and Alembic revision `0007_p0_customer_efficiency_events`; its only business value is one of four aggregate event types and its only replay metadata is `Idempotency-Key` plus a request fingerprint.
- Added B event intake, C-to-A aggregate summary, C Admin aggregate summary, and the read-only `/customer-efficiency` dashboard. The provider returns `summary_version`, `generated_at`, an explicit statistic window, five requested metrics, and no raw customer-service content or event detail.
- Defined adoption rate as `(direct adoption + edited adoption) / AI requests`, returning `0.0` when no AI-request events exist. Windows are UTC-aware `[start, end)` intervals.
- Added C-consumable `14_客服效率接口说明.md` because the frozen document itself is not available in this worktree. `contracts/**` remains unchanged; this does not claim a shared-contract promotion.
- No employee identity, ranking, performance evaluation, Prompt action, model training, knowledge publication, customer action, order change, or ERP write was added. Implementation commit: `12533e8` (`feat(platform): add customer efficiency metrics`).
