# C 试运行治理基础

## 目的与范围

本说明描述 C 运营中心在 test-only 试运行中的最小治理基础。它覆盖店铺、商品/SKU 导入、受控知识包、经验案例与 AI 反馈的内部运营路径，不改变 B 的提交接口、A 的读取/回写接口或 `contracts/**`。

数据流保持为：创建试运行店铺 → 目标绑定商品导入 → 受控知识包维护 FAQ/安全规则 → 人工审核经验案例或确认 AI 反馈 → 只读观察。没有自动发布知识、Prompt 修改、模型训练、ERP/订单写入或自动业务动作。

## 试运行角色

角色由服务端的固定试运行身份映射解析：

| 身份 | 角色 | 试运行能力 |
| --- | --- | --- |
| `trial-admin` | 管理员 | 安全运营读取、敏感内容读取、店铺/知识/审核/确认写入，以及审计元数据读取。 |
| `trial-operator` | 运营 | 安全运营读取、敏感内容读取、店铺/知识/审核/确认写入。 |
| `trial-support` | 客服 | 仅安全运营读取；不能读取案例或 AI 分析原文，也不能导入、创建店铺、审核或确认。 |

客户端使用 `X-Platform-Trial-Actor` 和 `X-Platform-Reason` 选择 test-only 上下文；服务端才执行固定角色矩阵。该头部不是登录凭据，不能证明用户身份。因此这不是正式认证、正式授权或生产 RBAC，不能用于生产数据保护声明。

## 路径与审计

- `GET /api/v1/admin/trial-governance`：返回当前试运行角色、能力和真实能力标记。
- `GET /api/v1/admin/trial-governance/audit-events`：仅 `trial-admin` 可读取无原文审计元数据。
- `POST /api/v1/admin/pilot-stores`、商品预检/导入、受控知识包导入、案例审核、AI 反馈确认要求管理员或运营角色。
- 案例原文、AI 分析原文及已批准案例/分析池的内部 Admin 读取要求管理员或运营；客服角色会得到 `TRIAL_ROLE_FORBIDDEN`。

审计表只写受控的动作、资源类型/标识、结果、目的代码和有限计数。它不写客户问题、AI 回答、客服回复、Excel 单元格、来源文件路径、自由文本原因、请求正文、令牌或真实身份信息。当前审计基础记录允许完成的受控操作；异常、恢复、留存与删除流程仍需要单独设计。

## 脱敏、留存与安全边界

当前 `v1-reminder-only` 仅表示提交/审核前的人工脱敏提醒。它不是自动脱敏，也没有自动检测、替换、验证或恢复功能。案例与反馈仍可能包含原始客服内容，必须仅使用 synthetic 或已脱敏 test-only 数据。

当前没有正式身份认证、正式授权、密钥管理、留存期限、删除策略、恢复审计或生产安全认证。上线前必须分别验证这些能力，并将敏感查看理由、授权来源、自动脱敏覆盖率和留存/删除结果纳入可审计的生产治理方案。
