# C-OPERATION-V1.1 daily operations snapshot

## Scope

`GET /api/v1/admin/operations/today` is a C-internal, read-only Admin projection for the 5174 AI operations center. It is not a B or A consumer API, does not modify `contracts/**`, and does not change any frozen cross-line field, error code, lifecycle, or database model.

The response contains only aggregate counts, operational queue state, current knowledge inventory, timestamps, and the existing trial-data flags. It never returns a customer question, AI answer, human answer, customer identifier, employee identifier, reviewer identity, idempotency key, event row, or source-document path.

## Window and metric definitions

The `today` window is the UTC interval `[00:00:00, generated_at)`. It uses the same UTC-day convention as `customer-efficiency.v1`.

| Field | Definition |
| --- | --- |
| `ai_request_count` | Content-free `AI_REQUEST` efficiency events whose `occurred_at` falls in the window. |
| `direct_adoption_count` | `DIRECT_ADOPTION` events in the window. |
| `edited_adoption_count` | `EDITED_ADOPTION` events in the window. |
| `not_adopted_count` | `NOT_ADOPTED` events in the window. |
| `adoption_rate` | `(direct_adoption_count + edited_adoption_count) / ai_request_count`, or `0.0` when no AI requests exist. |
| `experience_case_submission_count` | `CustomerExperienceCase` rows created in the window. |
| `ai_feedback_submission_count` | `AIResponseFeedback` rows created in the window. |
| `completed_ai_analysis_count` | Append-only AI analysis evidence recorded in the window. |
| `pending_experience_review_count` | Current cases in `NEW` or `REVIEWING`, independent of the day window. |
| `pending_ai_analysis_count` | Current feedback in `NEW` or `ANALYZING`, independent of the day window. |
| `open_knowledge_conflict_count` | Current knowledge conflicts whose status is not `RESOLVED`. |

Knowledge counts are current inventory counts for stores, products, SKUs, FAQs, and safety rules. `recent_imported_at` is the most recent test-package or import-batch timestamp.

## UI behavior and boundary

The Admin landing page calls this projection once, then separately probes existing C health and A module-directory endpoints for service availability. A failed source shows `待启用`; a real zero-value daily volume shows `样本不足`. The UI must not relabel inventory totals as daily volumes or fabricate a service/usage result.

This is a trial/test observation surface, not a formal report, staff-ranking system, performance-evaluation system, authentication boundary, audit log, retention mechanism, or production-security certification. It offers no Prompt modification, knowledge publication, automatic model training, customer action, order change, ERP write, or other automatic business execution.
