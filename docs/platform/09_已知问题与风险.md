# Known issues and risks

- SQLite is local-development only. Formal authentication, authorization, persistent audit logging, retention, deletion policy, and production security certification are not implemented.
- Experience-case content can contain sensitive customer-service text. The new C modules avoid logging it, but `v1-reminder-only` is not automatic redaction and the internal-test reviewer identity is not authenticated. Do not submit real customer data until a separately frozen authentication, authorization, retention, access-audit, and redaction design is implemented.
- Approved snapshots are immutable in C, but the local SQLite implementation is a development/test foundation and is not a production audit, recovery, retention, or privacy-security certification.
- Pilot-dashboard AI call count is a case-linked AI-answer proxy, not an AI request telemetry system. Its UTC service-day boundary and exact-question grouping are intentionally simple and must not be treated as formal operational analytics.
- The pilot page shows raw experience-case questions to the internal-test administrator. There is no formal authorization or automatic redaction, so real customer content must remain out of this environment.
- CORS is browser-origin control only, not authentication, authorization, CSRF protection, or a production-security guarantee.
- The prior A-line module detail and online-test contract/schema remains absent. The AI capability center controls remain unavailable/disabled rather than issuing guessed requests.
- Test catalog `publishable` source fields do not imply publication; package-level `production_usable=false` and `allow_auto_send=false` remain enforced by the baseline data model.
