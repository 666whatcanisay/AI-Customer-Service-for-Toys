# Known issues and risks

- SQLite is local-development only. Formal authentication, authorization, persistent audit logging, retention, deletion policy, and production security certification are not implemented.
- Customer-suggestion descriptions are not written to application logs, but the internal-test administration API does not itself provide formal identity verification or privacy classification. Do not use real customer data.
- The source-evidence API suppresses absolute paths and raw source contents; this is not a substitute for a full data-classification or document-security system.
- CORS is browser-origin control only, not authentication, authorization, CSRF protection, or a production-security guarantee.
- A-line module detail and online-test contract/schema is absent from this baseline. AI capability center controls remain unavailable/disabled rather than issuing guessed requests.
- Test catalog `publishable` source fields do not imply publication; package-level `production_usable=false` and `allow_auto_send=false` remain enforced by the baseline data model.
