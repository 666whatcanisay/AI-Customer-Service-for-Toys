# AI-CS C Operation Completeness Upgrade V1 Report

## 1. 改造目标

本次补齐 C 运营中心“店铺 → 商品 → SKU → 知识”的基础运营缺口：新增中文店铺管理、人工新增商品能力，并在商品知识详情中提供业务展示信息维护。同时把导入中心收敛为“创建店铺 → 新增/选择商品 → 导入商品知识”的中文引导流程。

本实现继续复用既有 `TestKnowledgePackage/TestStore/TestProduct` 试点目录和商品知识业务投影，没有进入 Master Data，没有新表、数据库迁移或底层 Store/Product/SKU 重构。

## 3. 功能说明

### 店铺管理

- 新增导航和 `/store-management` 页面。
- 列表只展示店铺中文名称、平台、状态、商品数量和创建时间。
- 新建只要求店铺名称、平台和备注；tenant、店铺编码、外部标识由服务端生成且不在页面展示。
- 支持查看和编辑店铺名称、平台、状态与备注。
- 同平台同名店铺会返回冲突，避免重复建档。
- 新店铺仍保持 `test_data_mode=true`、`production_usable=false`、`allow_auto_send=false`，不会自动创建商品或触发发布与客户动作。

### 商品基础信息

- `/store-management` 顶部和每个启用店铺行内均提供“新增商品”。
- 新增商品只填写所属店铺、商品名称和可选简介；内部商品身份、tenant、店铺编码与平台范围由服务端生成或继承。
- 新商品写入既有 `TestProduct`，创建轨迹为 `PRODUCT_CREATED`，初始固定为 `OFF_SALE`、`REVIEWING`、`publishable=false`，不会自动创建 SKU 或来源。
- 创建成功后店铺商品数真实刷新，商品立即进入现有商品知识中心，并可继续补 SKU 和知识资料。
- 同店铺同名商品会被拒绝，停用店铺不能新增；客户端额外提交技术身份字段会被拒绝。

- `/knowledge-center/products/{product}` 新增“编辑基础信息”。
- 可维护商品展示名称、商品简介、店铺展示名称和店铺展示备注。
- 商品内部身份、SKU 身份、正式名称和既有 SKU/FAQ/安全/来源记录均不改动。
- 商品展示名称或简介发生变化时，商品进入 `REVIEWING/PENDING_REVIEW` 且 `publishable=false`；只改店铺展示信息不会改变商品审核状态。页面立即同步显示，但不等于审核通过、AI 生效或 RAG 发布。

### 导入中心

- 导入中心新增中文店铺选择区和“店铺管理/创建店铺”入口。
- 没有可用店铺时显示真实空状态，不生成假数据。
- 新建店铺后可直接在导入中心选择；选择结果在当前浏览器会话中保留，并作为资料上传页的预选范围。
- 六类中文模板、受控上传审核和旧版兼容入口继续保留。

### C-only 接口

- `GET /api/v1/admin/operations/stores`
- `POST /api/v1/admin/operations/stores`
- `GET /api/v1/admin/operations/stores/{store_ref}`
- `PATCH /api/v1/admin/operations/stores/{store_ref}`
- `POST /api/v1/admin/operations/stores/{store_ref}/products`
- `PATCH /api/v1/admin/operations/products/{product_id}/basic-info`

这些接口属于 C Admin 内部能力，不是 A/B 或共享契约。请求不接受客户端 `tenant_id`、`store_code`、`external_id`，店铺业务响应也不返回这些字段。

## 4. 数据与生命周期边界

- 数据库结构与 Alembic head 均未改变。
- 店铺备注和轻量操作轨迹写入既有 `raw_data_json`；这不等同于正式权限审计系统。
- 编辑平台时只同步同一既有 package/store 范围内的 C 目录副本，不改变商品或 SKU 身份。
- 商品简介修改回到人工审核，不自动发布到 A、RAG，不自动训练模型或修改 Prompt。
- 未修改 `backend/**`、`frontend/**`、`extension/**`、`contracts/**`。
