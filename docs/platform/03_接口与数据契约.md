# 接口与数据契约

共享基础契约版本为 0.1.0，位置为共享仓库 contracts/。当前未确认的字段必须经契约提案；禁止直接访问其他线内部资源。

C-T02 只添加 C 线本地 `/api/v1/import-*` 接口，具体见 `data-ingestion/06_API说明.md`。本轮未修改 `contracts/**`，未建立 B→C 或 C→A 正式跨线契约。

行级问题契约固定为 `error_code/message/row_number/field/raw_value/suggestion`；批次成功响应同时提供 `id` 和同值 `batch_id`。共享化前仍需 schema、版本、CHANGELOG、兼容性说明和受影响线路审查。

C-T02A 新增 C 线本地 `POST /api/v1/import-batches/product-sku/preflight`。该接口不创建批次，返回文件/工作簿结构、质量汇总与 `can_import`；它不改变正式上传响应和最终商品字段。本接口仍未写入共享 `contracts/**`，详细响应见 `data-ingestion/11_XLSX导入前预检.md`。

C-T02B 按总控冻结了五个任务内只读响应：店铺、商品、SKU、RAG 导出和评测。C 线是这些响应的权威提供方；目录接口统一 `{items,total}`，包导出包含固定包级元数据，所有 `source_ids/component_sku_refs/expected_*` 等数组均返回 JSON 数组而不是逗号字符串。字段全集见 `data-ingestion/12_C-T02B测试数据包.md`。

兼容性结论：本轮未修改 `contracts/**`，未修改 A/B 业务代码，也未建立第二个 chat endpoint。A/B 后续只能按冻结字段消费；当前只完成 C 线数据库与 HTTP 响应验证，不宣称跨线真实联调通过。现有统一错误信封 `{error:{code,message,details?},request_id}` 保持不变。

C-T04 只增加 HTTP 浏览器来源配置，不改变任何 API 路径、字段、错误码或契约版本。`CORS_ALLOWED_ORIGINS` 是部署配置而非业务数据契约；允许来源由逗号分隔的完整 Origin 显式列出，禁止 `*`。`X-Request-ID` 继续通过 CORS 暴露给浏览器读取。
