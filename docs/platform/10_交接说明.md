# 交接说明

新 Agent 先阅读计划书、00、01 和 machine-context.json；只执行一张任务卡。完成后报告范围、未改内容、命令与结果、契约影响、风险、回滚和下一张建议卡。禁止修改：backend/**、frontend/**、extension/**。

C-T02 已建立可演示的商品/SKU XLSX 导入闭环；C-T02A 在其前面增加 `POST /api/v1/import-batches/product-sku/preflight`。管理端 `/imports/new` 必须先预检，只有 `can_import=true` 才开放正式上传。

关键不变量：有效行只能是 `PENDING_REVIEW`；错误或冲突不暂存；未审核数据不得发布到 A 线；不得接入金蝶或真实数据。共享 `contracts/**` 仍未修改。

预检没有数据库依赖，不应创建 `ImportBatch`、`ImportRow`、`StagedProductSku`，也不应要求先执行迁移；正式上传仍按 C-T02 使用数据库。

C-T02B 另建 `test_*` 隔离表和 `/test-data-packages` 管理页。ZIP 预检必须先验证完整 manifest/大小/SHA、V0.3.1 和四个测试安全标志；正式导入会重复全量校验并单事务写入。真实包不在 Git，附件/RTF 不写数据库二进制，也不由五个 GET 返回。

C-PACKAGE-FIX2 允许两种 ZIP 布局：根目录 `manifest.json`，或唯一一层安全外层目录下的 `manifest.json`。先完整校验物理 ZIP 条目，再只在内存中移除该目录前缀并以逻辑路径校验 manifest、workbooks 与证据；不解压、不改写上传字节。根/外层双 manifest、多顶层、两层包装、逻辑重复、路径穿越、绝对路径、符号链接和 manifest 外层路径引用均拒绝。原始 V0.3.1 ZIP 已通过正式 HTTP 预检/导入并得到 1/5/18/28/47；原始包保持只读且未提交。

当前发布阻塞仅为本机未安装 `gh`：按 GitHub 发布流程不能创建用户要求的 Draft PR。安装并认证 GitHub CLI 后，先复核 `git status` 与 60 项后端测试，再仅提交 C-PACKAGE-FIX2 范围并推送到 `develop` 的 Draft PR；不得自行合并。

五个冻结 GET 的字段与数组类型见 `data-ingestion/12_C-T02B测试数据包.md`。C 是权威提供方，但 A/B 尚未真实联调；不要创建第二套字段或第二个 chat endpoint。后续 C-T03、正式发布或跨线联调必须另行授权，不得自动执行。

C-T04 后，OPS 启动 C 服务时应设置 `CORS_ALLOWED_ORIGINS=http://127.0.0.1:5173` 并使用端口 8011，不再通过临时 Python 包装器注入 CORS。需要兼容 `http://localhost:5173` 时必须显式加入逗号列表；禁止使用 `*`。总控最终联调应同时验证允许来源预检/实际响应、拒绝来源无许可头、`X-Request-ID` 可读，以及停止脚本只关闭自己启动的进程。
