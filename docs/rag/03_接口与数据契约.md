# 接口与数据契约

## AI 质量基线诊断 V1（2026-07-27）

新增向后兼容的只读 `GET /api/admin/ai/quality-baseline/latest`，沿用 `{success, message, data}` 包装，并以 Pydantic `QualityBaselineResponse` 生成 OpenAPI。它不修改 `contracts/**`、C 接口、错误码、已有管理端点或冻结评测文件。

- schema：`ai-quality-baseline.v1`；仅选择最新保存、`evidence_mode=live_c_api` 的报告。
- 输出：安全的评测总数/通过数/检查通过数、失败 CASE 标识、评测器失败类、失败检查、来源/事实数量、分类结论和人工验证建议。
- 归因：`metadata_loss→DATA_PROBLEM`、`retrieval_miss→RETRIEVAL_PROBLEM`、`model_expression_error→PROMPT_OR_MODEL_PROBLEM`、`structured_decision_error→RULE_DECISION_PROBLEM`；`key_facts` 失败同时给出 `KNOWLEDGE_PROBLEM` 信号。分类可以重叠，不能相加为总失败数。
- 隐私：绝不返回 question、answer、source excerpt、expected fact、source ID、Prompt、平台 URL、密钥或异常原文。`raw_content_exposed=false` 固定。
- 控制：`model_or_prompt_changed=false`，每项建议 `automatic_change_allowed=false`。GET 不调用 qwen、C 或检索，也不修改知识、Prompt、规则或模型。

该接口是评测报告的可追溯解释层；它不产生新评测，也不把无 `model_expression_error` 的结果解释为 Prompt 已被证明正确。

## AI 运营概览 V1（2026-07-27）

新增向后兼容的只读 `GET /api/admin/ai/operations/overview`，沿用 `{success, message, data}` 包装，并以 Pydantic `AiOperationsOverviewResponse` 生成 OpenAPI。它不修改 `contracts/**`、既有 C 接口字段、错误码或 `ai-control-center.v1.1`；现有消费者可继续使用原端点。

- schema：`ai-operations.v1`；根字段为 `answer_volume`、`answer_quality`、`knowledge_coverage`、`badcase`、`model_status`、`external_data` 和 `notices`。
- 回答量：只含 A 进程启动后的请求总数与 `DIRECT_ANSWER`、`CONTROLLED_ANSWER`、`TRANSFER_HUMAN`、其他结果计数；重启清空，不能作为人员绩效或历史审计数据。
- 质量：只读取已有 `live_c_api` 评测的通过数/总数；覆盖率只读取其中 `source_ids` check 通过数/总数。两者均带解释，且不代表全量生产会话或全量知识库覆盖。
- Badcase：固定四类 `FACT_ERROR/MISSING_INFO/STYLE_ISSUE/RISK_ISSUE`，count 为 `null`，`raw_content_exposed=false`。A 不读取 C 原始反馈，也不从反馈分析回执推断分类数。
- C 数据：feedback 仅报告配置与当前进程安全聚合是否存在；效率状态为 `NOT_REGISTERED`，因为 A 范围没有已审核、去标识化、聚合-only 的效率摘要契约。GET 的 `read_attempted=false`，不主动请求未知 C 路径。
- 诊断：`notices` 只返回受控 code、等级、说明和人工操作建议，`automatic_action_taken=false`；不会改 Prompt、发布知识或训练模型。

若后续增加 C 效率摘要消费，必须先完成 schema/version/changelog/兼容性/受影响线路评审，明确仅含聚合指标、窗口与去标识化边界；A 不得猜测字段或直接读取 C 内部数据。

## AI-CONTROL-V1.1 控制中心快照（A -> 必要 AI UI）

本任务新增向后兼容的只读 `GET /api/admin/ai/control-center`，使用现有 `{success, message, data}` 包装，并以 Pydantic `AiControlCenterResponse` 生成 OpenAPI。它不修改 `contracts/**`、C 接口、错误码或既有 `/api/admin/ai/modules/*` 行为；V1.0 的多个 GET consumer 可继续使用，V1.1 UI 迁移为一次读取统一快照。

- `data.schema_version` 固定为 `ai-control-center.v1.1`。未知版本、字段类型错误或字段缺失在前端 adapter 中作为契约错误处理，不回退样例数据。
- `customer_service`：仅包含 A 进程的模型、知识块和 `since_start` 调用聚合；重启清零。它不包含初始化异常原文、请求正文或来源正文。
- `prompt`：仅含模块 ID、版本、hash、代码管理标识、安全预览和风格规则；不含完整 Prompt、系统信息、环境变量或密钥。
- `evaluation`：读取已有 `live_c_api` 报告的安全摘要；`current_model_version/current_prompt_version` 是当前 A 配置，不是历史评测快照。报告无可读数据时为 `NOT_AVAILABLE`。
- `badcase`：固定列出 `FACT_ERROR/MISSING_INFO/STYLE_ISSUE/RISK_ISSUE`，所有 count 为 `null`。A 不在浏览器 GET 中访问 C 原始快照或推断分类，`raw_content_exposed=false` 固定。
- `feedback_analysis`：C 集成未配置时为 `NOT_CONFIGURED`；配置后也只能 `MANUAL_ONLY`。最近运行只保留完成时间、输入/完成/写回/幂等聚合数及单一模型/PROMPT 版本；没有 feedback_id、analysis_run_id、revision、content_hash、分析文本或建议文本，且进程重启后为 `null`。
- `capabilities` 和 `data_sources` 仅为技术负责人展示状态、数据可用性、人工边界和脱敏来源说明；快照 GET 不探测 C、不发起 qwen、也不运行任何分析。

兼容影响：前端 V1.1 使用共享 `RagClientError` 映射 HTTP/网络/契约异常；后端原端点保持可用。该 UI 消费变更由本任务明确授权，未要求 B/C 修改业务代码。若将来扩展共享管理 API，必须另行提供 schema、版本、changelog、兼容说明和受影响线路评审。

## MVP-PLUS-02 AI 反馈分析消费者

本任务只消费 C 已冻结的 `ai-feedback.v1` 接口，未修改 `contracts/**`、接口版本、字段或错误码。A 只读 `GET /api/v1/admin/ai-quality/badcases` 中人工确认的不可变快照，并只向 `POST /api/v1/admin/ai-quality/analysis-results` 回写分析证据。

写回字段严格保留 C 导出的 `feedback_id`、`revision`、`content_hash` 和闭集 `feedback_type`（`FACT_ERROR`、`MISSING_INFO`、`STYLE_ISSUE`、`RISK_ISSUE`、`OTHER`），并补充 A 生成的 `analysis_run_id`、`model_version`、`prompt_version`、`analysis` 与 `suggestions`。相同完整载荷的同一 `analysis_run_id` 回放由 C 幂等处理；A 不消费未提供的 `/feedback-cases` 路径。

A 新增的 `POST /api/admin/ai/feedback-analysis/run` 是本机显式运维入口，不是 B/C 跨线接口。它仅允许 loopback 调用，接受 `{ "maximum": 1..100 }`，不支持后台轮询或自动业务动作；响应仅含安全追溯回执，不含原始问答内容。

共享 contracts 仍为 0.1.0 且未修改。A-T03 使用总控冻结的任务内 V0.3.1 兼容约定，不创建第二套跨线接口。

## C -> A

- `GET {PLATFORM_API_BASE_URL}/api/v1/test-knowledge-packages/{package_id}/rag-export`
- `GET {PLATFORM_API_BASE_URL}/api/v1/test-knowledge-packages/{package_id}/evaluations`

包级必须为：`TENANT-PDD-SM-TEST / pdd / PDD-SM`、`version=V0.3.1`、`schema_version=0.3.1-test`、`test_data_mode=true`、`production_usable=false`、`response_mode=SUGGESTION_ONLY`、`allow_auto_send=false`，且 `total` 等于 items 数量。任一字段不符即拒绝同步。

`PRODUCT_FACT` 必须有 product_id；`SKU_FACT` 必须同时有 product_id 与 sku_id；FAQ 默认必须有 product_id，只有 product_id/sku_id 均空、risk_level=HIGH 且动作为 ASK_CLARIFY/REQUIRE_LOOKUP/TRANSFER_HUMAN/REFUSE 时才允许作为店铺级安全 FAQ；`SAFETY_RULE` 可为空商品/SKU。其他空商品事实一律拒绝。

## A chat

唯一新规范仍为 `POST /api/chat`：

```json
{
  "question": "Q80有多少颗？",
  "context": {
    "tenant_id": "TENANT-PDD-SM-TEST",
    "platform": "pdd",
    "store_code": "PDD-SM",
    "product_id": "P-Q80",
    "sku_id": null
  }
}
```

`data` 权威字段固定为 `answer/action/risk_level/sources/warnings/required_fields/model/latency_ms/request_id/context`。source 固定为 `source_name/page/chunk_id/distance/excerpt/knowledge_version/source_ids/product_id/sku_id`。旧 `message` 只允许无 context 的兼容请求；新调用必须提供 question 与冻结 context。

`required_fields` 只表示当前回答前仍需补收的字段：context 已提供的 tenant/store/product/SKU 不得重复返回；只有 `ASK_CLARIFY`、`REQUIRE_LOOKUP`、`TRANSFER_HUMAN` 可返回缺失字段。action、risk、required_fields 与 source_ids 在模型调用前由范围、知识元数据和通用安全意图确定，模型不得自由改写这些结构化字段。

同步触发使用 A 线本机接口 `POST /api/test-knowledge/sync/{package_id}`；未配置 C 地址返回 `503 ENV_BLOCKED`，格式或安全字段错误返回 422。

## MVP-PLUS-01 C -> A -> C 受控评测

新增任务内冻结接口，不修改 `contracts/**`：A 仅经 `GET {PLATFORM_API_BASE_URL}/api/v1/admin/ai-optimization/cases/export` 消费 C 已批准、不可变且尚未评测的案例快照；它不读取 C 数据库。A 的人工入口是 `POST /api/admin/ai/experience-evaluations/run`，请求仅为 `{case_id, revision}`。

找到精确 snapshot 后，A 调用已配置的真实本机 Ollama，要求产生受限 `result/suggestions` JSON。只有解析和字段校验成功才调用 `POST {PLATFORM_API_BASE_URL}/api/v1/admin/ai-optimization/evaluation-results`；回写必须原样传递 snapshot 的 `case_id`、`revision`、`export_revision` 和 `content_hash`，并带入实际 `model_version`、受版本控制的 `prompt_version` 与新 `evaluation_run_id`。

固定错误：`EXPERIENCE_EVALUATION_EXPORT_UNAVAILABLE` (503)、`EXPERIENCE_EVALUATION_MODEL_UNAVAILABLE` (503)、`EXPERIENCE_EVALUATION_OUTPUT_INVALID` (422)、`EXPERIENCE_EVALUATION_WRITEBACK_FAILED` (502)。无轮询、重试写入、Prompt 自动修改、知识发布、客户发送或 ERP 动作。详见 `experience-evaluation.md`。
