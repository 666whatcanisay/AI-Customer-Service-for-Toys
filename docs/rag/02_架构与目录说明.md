# 架构与目录说明

A-T03 只修改 A 线 `backend/**` 与 `docs/rag/**`，消费总控冻结的任务内 V0.3.1 兼容约定，不修改共享 contracts 或 C 线实现。

```text
C GET /rag-export
  -> PlatformTestKnowledgeClient
  -> version V0.3.1 + schema 0.3.1-test strict validation
  -> TestKnowledgeIndex
  -> Chroma collection: test_knowledge_v031

POST /api/chat {question, context}
  -> exact tenant/platform/store/product filters
  -> exact SKU first; product-level fallback; same-product comparison when SKU absent
  -> structured action/risk/required_fields/source decision
  -> Ollama only organizes DIRECT_ANSWER / CONTROLLED_ANSWER wording
  <- frozen data response + citations + echoed context
```

原 `documents` Collection 与 PDF 链路保持不变。测试知识使用独立 Collection；同步采用稳定内容 ID 与 upsert，重复同步不会增加记录，也不会清空或覆盖原索引。

范围查询固定为 `TENANT-PDD-SM-TEST / pdd / PDD-SM`。有 SKU 时只允许精确 SKU 与同商品的空 SKU 商品级知识；无 SKU 时允许同商品内 SKU 比较，但仍禁止跨商品。索引文档使用 `title + content` 提升命中，回答和引用仍使用 C 原始 content；紧凑 SKU_FACT 中的第二个裸数字仅在回答上下文中标注为颗粒数，不改写 C 数据。额外店铺级查询只允许 `SAFETY_RULE`，或 product/SKU 均空、HIGH 且动作为 ASK_CLARIFY/REQUIRE_LOOKUP/TRANSFER_HUMAN/REFUSE 的 FAQ；普通商品事实回答不会用无关店铺级来源凑 source_ids。评测中空商品 case 使用内部 sentinel，不放宽公开 chat 的 product_id 必填。所有查询同时限制 `test_data_mode=true`、`production_usable=false`。

评测器按中文标点/空白、数字单位、同义表达逐事实判断，并要求数字与单位相邻、来源与当前商品/SKU 范围兼容；否定提及不算正向事实命中。报告逐案记录预期/实际 action、risk、required_fields、source_ids、关键事实、回答和失败分类。
