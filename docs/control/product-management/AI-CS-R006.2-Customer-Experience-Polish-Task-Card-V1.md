## 目标

在不改变 R006 状态模型和跨系统职责的前提下，让已打开的 B 客服页面通过窗口重新获得焦点和低频安全检查感知 C 目录变化，并让 C Admin 的批量启用操作更清楚、可控。

## 范围

- B 在页面重新获得焦点时刷新当前客服可用目录。
- B 保留手动刷新，并增加页面可见期间的低频目录检查；页面卸载时停止。
- C Admin 显示当前待启用数量，支持人工全选当前筛选结果。
- C Admin 启用成功后提示“客服工作台刷新目录后即可使用”。
- 补充 B/Admin 单元测试、类型检查、构建和隔离浏览器验收。

不包含：

- 不修改 R006 状态、接口或数据库结构。
- 不修改 R009、A、RAG、Prompt、Import Center。
- 不引入 WebSocket、SSE、自动启用、自动发送、退款或订单操作。
- 不切换或停止当前正式 Runtime。

## 成功标准

1. B 页面重新获得焦点时刷新 Store 和当前 Store 的 Product 投影，且不清空仍然有效的当前咨询。
2. B 在页面可见期间每 60 秒进行一次安全目录检查，卸载后停止定时器与事件监听。
3. 目录中当前已选商品被停用或移除时，B 清除失效 Product/SKU/回答上下文。
4. Admin 显示当前 Store 的待启用数量，可全选/取消全选当前筛选中的合格商品，批量启用仍需操作人和人工点击确认。
5. 批量启用成功提示包含“客服工作台刷新目录后即可使用”。
6. B/Admin 测试、类型检查、构建和隔离浏览器验收通过。

## 风险与缓解

- 自动刷新不得打断客服正在编辑或查看的有效咨询；仅在当前选择失效时清理上下文。
- 低频检查只在页面可见且无同类请求执行时运行，避免请求叠加。
- “全选”只改变前端选择，不直接调用启用接口；正式状态仍由运营填写操作人并点击批量启用后改变。
- 浏览器验收使用隔离数据库和非正式端口，正式 Pilot 保持运行。
