## 目标

基于当前 B 客服工作台和 C 运营管理中心的真实路由、导航与页面内容，形成不改变功能、接口、数据和业务流程的 UI 信息架构优化计划。

## 本轮范围

- 盘点 C Admin 当前导航、首页、商品知识中心、导入中心、AI 控制中心的信息层级。
- 盘点 B 客服从选择店铺到核对回答的主任务路径。
- 设计简洁模式、高级模式、渐进展开与首页工作台结构。
- 明确普通运营、管理员、客服和技术运维的信息边界。
- 给出后续 UI 实施优先级与验收标准。

## 禁止范围

- 不新增业务模块，不修改现有业务流程。
- 不修改数据库、API、contracts、R006、R009、A、RAG 或 Prompt。
- 不修改 B/C UI 代码，不重启或切换 Runtime。
- 不把“高级模式”解释为登录鉴权或权限控制。

## 所有权

- B 体验边界：`frontend/**`、`docs/customer/**`。
- C 体验边界：`admin_web/**`、`docs/platform/**`。
- 本轮仅由 Control 输出跨线 UI 架构计划；后续实施仍须按 B/C 所有权拆分。

## 成功标准

1. 方案明确当前菜单数量、主路径问题和真实页面证据。
2. 新菜单结构可以映射到全部现有核心路由，不丢功能。
3. 简洁/高级模式只控制信息展示，不改变权限和业务语义。
4. 首页指标只使用现有真实数据；无来源的数据不得伪装成“今日”指标。
5. B 客服安全提示、人工确认、回答依据和商品上下文不得被隐藏。
6. 输出计划、看板、变更记录、交接和 machine-context 同步完成。

## Gate

完成本任务只表示 `UI_ARCHITECTURE_PLAN_READY`。后续任何 UI 修改均需另立实施任务、按 B/C 所有权开发并完成浏览器回归。
