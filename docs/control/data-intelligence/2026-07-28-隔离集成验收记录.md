## 隔离条件

- 使用独立 SQLite、受忽略 `.runtime/integration/`、隔离端口 C `18011`、A `18000`、B `15173`、Admin `15174`。
- 未停止或改写既有 `8000`、`8011`、`5173`、`5174` 服务及其数据。
- 使用原始 V0.3.1 测试 ZIP 的独立导入，以及两份去标识化 CSV 资料样例；无客户、订单、地址、电话、支付或密钥。
- B 使用显式调试直连 C/A 以便隔离端口验收；正式运行默认的同源代理配置未改动。

## 真实闭环证据

1. C 接收去标识化 CSV，返回 `RECOGNIZED`、不可变 revision `1`、`sha256:` 内容哈希及中文识别摘要。
2. 运营审核将该版本变为 `APPROVED_FOR_ANALYSIS`；A 的输入导出只返回这份审核后的摘要快照。
3. A 通过显式人工触发调用本地 `qwen3.5:9b`，并以 `knowledge-quality.v1` 生成结构化中文缺口；C 已保存对应 `analysis_run_id`、模型/Prompt 版本和 `ANALYZED` 状态。未使用 Mock 成功结果。
4. C Admin 的“资料质量与补充”页面显示中文摘要、缺口数量和“已完成分析”；未显示原始上传文件或模型思维链。
5. 运营用相同资料编号上传修正内容，C 创建 revision `2`，保留 revision `1` 的审核和分析证据；没有覆盖旧版本。
6. B 真实浏览器选择 V0.3.1 测试商品后，先显示“暂无已审核资料”；在修正版本进入识别状态后显示“回复前需要人工核对”。这只读提示未阻断现有选品、提问和生成建议操作。

## 已验证的安全边界

- 上传、审核、分析和修正均未自动发布到 RAG。
- 没有自动改 Prompt、模型或训练；没有自动发送客户消息、售后、退款、订单或 ERP 写入。
- B 不显示原始资料、内容哈希、缺口正文或技术错误。
- A 对 C 的合法多行资料摘要只作内存分析；控制字符仍拒绝，且模型/平台失败不会伪造分析成功。

## 真实限制

- 隔离 A 未同步独立 C 的 RAG 测试知识，因此一次既有客服问题真实返回了 `NO_SCOPED_KNOWLEDGE` 安全兜底；这不是资料质量闭环的“已发布知识”成功，不能把它表述为知识已上线。
- 本 V1 的目的就是让客服看到可人工核对的资料状态，不改变现有 RAG 发布流程。资料修正需要未来独立、人工控制的知识生命周期流程才可能进入检索。
- 该记录只证明候选分支的隔离集成；合并、正式启动与内部试运行仍需要单独授权和 Gate。

## 结论

浏览器复验确认资料页已将 `RECOGNIZED` 显示为“已识别，待审核”，其余生命周期状态也以中文业务标签呈现；运营人员不需要读取原始枚举。候选实现可进入合并审查，结论为 `TARGET_MODE_READY (candidate)`；不得将其表述为已部署或对外生产可用。
