# 商品资料准备与上传指南（试运行）

## 这份资料用来做什么

这套模板帮助运营把商品规格、安全说明、拼装说明和常见问答整理成可审核的资料。系统会先识别资料是否完整，再由运营人工确认；只有人工确认后的资料摘要才可供 AI 做“资料缺口分析”。

上传、审核或分析成功都**不代表**资料已经进入 AI 客服知识库。当前试运行不自动发布知识、不自动改 Prompt、不自动训练模型，也不会自动发送客户消息或变更订单。

## 上传前先确认

1. 一份资料只对应一个店铺和一个商品；某一具体款式可填写 SKU。
2. 资料必须来自已核对的商品包装、说明书、规格页或已批准 FAQ。
3. 不要填写客户姓名、手机号、收货地址、订单号、身份证件、支付信息或聊天记录。
4. 不确定的事实请留空并在“检查备注”说明；不要猜测、不要用“可能”“大概”补全。
5. 每次修正请新建资料版本重新上传，已审核版本不会被覆盖。

## 使用模板的四步

1. 下载或复制 [商品资料模板.csv](商品资料模板.csv)，删除示例行后填写真实的去标识化商品资料。
2. 在运营中心的“商品知识 → 资料导入”选择文件，并依次选择店铺、商品和可选 SKU。
3. 检查系统返回的“已识别字段”和“待补全字段”。识别正常也不等于资料已审核。
4. 由运营在详情页核对，进入“审核中”，确认无误后选择“允许 AI 分析”。

文件上传后，请记录页面显示的资料名称、版本和上传时间，便于后续核对。不要将原始资料文件、截图或导出内容提交到代码仓库。

## 字段填写说明

| 字段 | 怎么填 | 示例 | 不能填什么 |
| --- | --- | --- | --- |
| `store_code` | 已存在的店铺编码。 | `PDD-SM` | 客户昵称、平台账号密码。 |
| `product_id` | 已存在的商品标识。 | `PRODUCT-001` | 自行编造且无法对应商品的名称。 |
| `sku_id` | 资料只适用于某一款式时填写；通用资料可留空。 | `SKU-001` | 客户订单号。 |
| `material_type` | 选一种：`PRODUCT_SPEC`、`SAFETY_INSTRUCTION`、`ASSEMBLY_GUIDE`、`FAQ_SOURCE`、`OTHER`。 | `SAFETY_INSTRUCTION` | 多种类型写在一个枚举里。 |
| `display_name` | 让运营看得懂的资料名称。 | `陆战坦克安全说明` | 客户姓名、手机号。 |
| `适用年龄` | 已确认的年龄范围。 | `6-12岁` | “所有年龄都适用”等未经确认结论。 |
| `安全提示` | 包括小颗粒、成人陪同、使用限制等。 | `不适合3岁以下儿童` | 绝对安全承诺、医疗建议。 |
| `包装清单` | 实际内含物。 | `颗粒、说明书、贴纸` | 未核实的配件。 |
| `拼装说明` | 关键步骤、前置条件或风险点。 | `先分类零件再按图拼装` | 复制客户聊天记录。 |
| `常见问答` | 可复用、已核对的问题与事实回答。 | `适合几岁？6-12岁` | 含收货地址、订单、售后承诺的对话。 |
| `资料来源` | 包装、说明书或批准的内部来源。 | `包装说明书 2026-07 版` | 密钥、外部登录链接。 |
| `维护人` | 负责核对资料的内部人员标识。 | `运营-小李` | 客户姓名或联系方式。 |
| `检查备注` | 待确认项和核对范围。 | `待补充包装清单` | 敏感资料、长篇原始文本。 |

## 资料完整性的最低检查

不同资料类型的必填业务内容不同。以下是试运行最低建议：

| 资料类型 | 至少应有 | 常见缺口 |
| --- | --- | --- |
| 商品规格 | 商品/SKU范围、适用年龄、规格或颗粒数 | 没有包装清单、款式不明确 |
| 安全说明 | 年龄限制、安全提示、成人陪同要求 | 只写“注意安全”而没有具体限制 |
| 拼装说明 | 适用款式、关键步骤、风险点 | 没有说明零件是否可同时组装 |
| FAQ 来源 | 问题、经过核对的事实答案、适用范围 | 把临时客服承诺当成通用规则 |

系统识别到缺口后，会给出资料质量提示。请根据原始、经过确认的商品资料修正，再上传形成新版本；不要为了让提示消失而编造内容。

## 状态是什么意思

| 状态 | 意义 | 运营下一步 |
| --- | --- | --- |
| 已接收 | 文件已保存，等待识别。 | 等待识别结果。 |
| 已识别 | 系统已提取字段摘要。 | 人工核对字段与范围。 |
| 审核中 | 运营正在核对。 | 补充或退回不可靠内容。 |
| 允许 AI 分析 | 已确认可将去标识化摘要交给 AI 做质量分析。 | 等待或手动发起分析。 |
| 分析完成 | 已得到缺口建议。 | 按建议核对原始资料并创建新版本。 |
| 已拒绝 / 分析失败 | 资料或分析不满足要求。 | 看中文原因，修正后重新提交。 |

“分析完成”只表示运营获得资料质量建议；它不代表知识发布、客服自动使用或对客户的承诺。

## 出错时怎么处理

| 页面提示 | 先检查 | 不要做 |
| --- | --- | --- |
| 文件不支持 | 使用 CSV、允许的文档格式，确认文件没有损坏。 | 修改后缀伪装文件格式。 |
| 资料范围不匹配 | 店铺、商品、SKU 是否真实存在且对应。 | 为了上传成功随便选商品。 |
| 存在敏感信息提醒 | 删除客户/订单/地址等内容，改为商品事实。 | 把敏感信息写进备注。 |
| 待补全字段 | 回到包装或说明书核对。 | 让 AI 或客服猜测。 |
| AI 分析不可用 | 记录时间与中文错误，稍后重试或联系技术管理员。 | 手工伪造“分析成功”记录。 |

## 运营修正闭环

```text
准备去标识化资料 → 上传并识别 → 人工审核 → AI 发现资料缺口
                                         ↓
客服只看到简短核对提示 ← 运营依据原始资料修正并上传新版本
```

客服端不会展示原始资料、哈希、AI 分析正文或技术错误。客服仍须对 AI 建议和商品事实做人工确认。
