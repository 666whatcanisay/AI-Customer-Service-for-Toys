# 资料质量闭环集成验收计划

## 目的与边界

本计划验证 `knowledge-quality-loop.v1` 的最小、真实、受控闭环：

```text
运营上传去标识化资料 → C 识别与人工审核 → A 真实模型发现资料缺口
→ C 显示建议并创建修正版本 → B 向客服显示紧凑状态 → 客服继续人工确认地使用 AI 问答
```

它不验证自动知识发布、模型训练、Prompt 修改、客户消息、售后、退款、订单或 ERP 动作，因为这些能力不在 V1 范围。

## 前置条件

- C、A、B 必须来自同一个已合并的 Git 提交或由运行时 SHA 检查确认兼容。
- C 可用、A 使用已配置的本地模型且模型身份可被读取、B 能通过既有同源代理调用 C。
- 仅使用 `商品资料模板.csv` 的替换后去标识化示例；禁止上传真实客户、订单、地址或支付数据。
- 保留资料标识、revision、hash 前缀、`analysis_run_id`、时间和 HTTP 结果；不保存原文、密钥、完整 Prompt 或思维链。

## API 验收矩阵

| 阶段 | 操作 | 预期真值 | 失败时的正确行为 |
| --- | --- | --- | --- |
| C 上传 | 带稳定 `Idempotency-Key` 上传资料。 | 返回资料标识、revision、`sha256:` hash 和中文识别摘要。 | 校验/格式/范围错误清晰返回；不创建半成品。 |
| C 幂等 | 用相同键和相同资料重试。 | 返回同一 receipt；不创建第二个版本。 | 同键不同资料返回 409 冲突。 |
| C 审核 | `RECOGNIZED → REVIEWING → APPROVED_FOR_ANALYSIS`。 | 审核人、时间、备注和版本可追溯。 | 越级或旧 revision 返回状态/版本错误。 |
| C → A | 查询 approved analysis input。 | 仅出现审核的 immutable snapshot，无原始文件。 | 未审核资料不可见。 |
| A 分析 | 显式发起一次质量分析。 | 真实模型结果含 `analysis_run_id`、模型/Prompt 版本、中文摘要和结构化 gaps。 | 模型/输出/C 不可用时失败，不写伪造成功。 |
| A → C | C 接收 analysis result。 | revision/hash/run ID 精确匹配并进入 `ANALYZED`。 | body 不匹配返回错误，旧结果仍可追溯。 |
| C 修正 | 运营按原始资料补全一个缺口。 | 新上传创建 revision+1；旧 approved/assessment 未覆盖。 | 不允许直接覆盖 approved revision。 |
| B 提示 | 选中对应商品/SKU。 | 仅中文状态、摘要、检查时间；不泄露材料或分析正文。 | C 不可用显示可继续咨询的明确提示，不显示“暂无数据”。 |
| B 既有流程 | 正常提问、得到 AI 建议、复制。 | 知识状态不阻断选品、问答、复制、案例或反馈。 | A/C 状态错误不改变客服人工确认边界。 |

## 浏览器验收路径

1. 在 C 运营中心打开“商品知识/资料导入”，下载模板，核对引导与数据隐私提醒为中文。
2. 上传一份去标识化资料，记录 receipt 的无敏感标识；确认“已识别字段”和“待补全项”并非原始 JSON 堆砌。
3. 以运营身份完成审核状态流转，确认不存在“直接发布到知识库”的按钮或暗示。
4. 在 A 控制入口显式运行一次质量分析，观察模型不可用时失败、可用时显示可追溯结果；不得把本地假数据当作模型回答。
5. 回到 C 的质量建议池，确认缺口、严重度和建议均为中文摘要，技术详情折叠。
6. 依据核对过的商品事实修正资料并上传新 revision，确认旧记录保留。
7. 在 B 工作台选择同商品/SKU，确认只出现紧凑资料状态，并完成一次既有 AI 问答和复制动作。

## 异常、安全与回归

- C 返回 503：B 不阻塞且不把错误伪装成空数据。
- A 模型不可达或结构输出无效：不写入成功 assessment，C 显示可恢复中文状态。
- 非法文件、同幂等键不同内容、过期 revision、未审核导出和不匹配 writeback 都必须被拒绝。
- 原始文件、客户信息、日志、数据库、`.runtime`、向量库和构建产物不得被提交。
- 验收不允许自动调用任何知识发布、Prompt/模型修改、训练、发送或业务执行 API。

## 通过判定

只有同时满足下列证据才可称为 `TARGET_MODE_READY`：

1. C 的实际上传/识别、审核与新 revision 证据；
2. A 对 C 的 approved snapshot 进行真实模型调用的结果与 `analysis_run_id`；
3. C 已持久化并以运营可读方式展示相同版本的质量建议；
4. B 的紧凑提示和一条未被阻断的真实客服问答/复制路径；
5. 范围、安全、回归、工件检查均通过。

缺少真实模型、未能写回 C、使用 Mock 成功结果，或把资料状态误表述为“已发布知识”，均为 `BLOCKED`。
