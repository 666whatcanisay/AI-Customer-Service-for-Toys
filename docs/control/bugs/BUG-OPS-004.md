# BUG-OPS-004 — 停止脚本可能在部分服务残留时返回成功

- 等级：P1
- 模块：OPS / Windows Runtime stop
- 状态：FIXED_VERIFIED
- 发现时间：2026-08-01

## 现象

长时运行后执行标准停止流程，A/C 已停止；B/Admin 的 WMI 进程元数据查询一次超时，身份校验安全拒绝停止，但顶层脚本仍返回退出码 0，形成“部分停止”。

## 原因

- 有界 WMI 查询能够避免无限阻塞，但偶发超时时只返回一次失败，没有重试。
- `Stop-ManagedService` 的安全拒绝以 warning 返回，顶层停止入口没有在结束前检查剩余运行记录和四个标准端口。

## 修复

- 身份查询失败时有界重试一次；不放宽 PID、路径、启动时间、命令、父子关系或端口所有权条件。
- 停止流程结束后检查四个受管记录和 5173/5174/8000/8011。
- 存在任何残留时返回非零和明确原因；绝不按端口终止未知进程。

## 验证

- 原现场第二次严格身份检查成功停止 B/Admin，四端口全部释放。
- 修复后 10/10 Windows OPS 测试通过。
- 正式 stop/start/status 回归要求四端口全部释放后才允许记录 PASS。
