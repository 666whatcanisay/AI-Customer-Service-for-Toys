## MVP-PLUS-02 交接

当前分支为 `codex/customer-pilot-experience`，仅改动 `frontend/**` 和 `docs/customer/**`。本任务不改变后端字段、CustomerExperienceCase adapter、共享契约或任何 A/C 网络调用。

首次拥有测试客服身份的进入者会看到“AI客服助手（测试版）”引导：选择商品/SKU、输入客户问题、查看 AI 建议、人工确认后复制发送、好回复可收藏为优秀案例。关闭引导只在本机保存一个已阅读布尔标记；不是认证、权限或培训凭据。

AI 回答页保留原流程和三种反馈。动作展示为 `DIRECT_ANSWER=🟢 可以参考`、`CONTROLLED_ANSWER=🟡 建议确认`、`TRANSFER_HUMAN=🔴 建议人工处理`；不改变 A 返回 action。案例入口文案为“⭐ 收藏为优秀案例”，仍使用既有真实 CustomerExperienceCase POST 和表单中显式选择的冻结经验类型。

选择“未采用”后会出现独立“AI 问题反馈”入口。它打开“为什么未采用？”弹窗，使用 `FACT_ERROR/MISSING_INFO/STYLE_ISSUE/RISK_ISSUE/OTHER`（事实错误/缺少信息/表达问题/风险问题/其他）；`OTHER` 必须填写去标识化说明。该表单调用唯一真实路径 `POST /platform-api/api/v1/ai-response-feedback`，不会发送到经验案例接口，也不会写入 localStorage。

AI 反馈 adapter 严格发送 `store_code/product_id/sku_id/question/ai_answer/feedback_type/feedback_note/final_answer/created_by/context`；context 只含店铺、商品、SKU 且须与顶层一致。成功只接受顶层 `feedback_id/status=NEW/analysis_status=NEW/created_at`，再显示“反馈已记录。”；失败不会生成本地成功或回退为优秀案例。不要在 B 中增加反馈历史 GET、C Admin/A 导出、状态变更、自动脱敏、Prompt/知识修改或客户/订单操作。

最近验证（2026-07-25）：`vue-tsc --noEmit` PASS；Vitest 22 个文件、87/87 PASS；`vite build` PASS。构建仍有单个 JavaScript chunk 超过 500 kB 的既有警告。

GitHub CLI 浏览器认证已复核恢复。下一步为复核范围、暂存本任务的 `frontend/**` 与 `docs/customer/**` 文件、提交、push 并以 `feat(customer): add AI feedback capture` 创建 Draft PR。

## MVP-PLUS-01 交接

当前分支为 `codex/customer-experience-case-capture`，Draft PR #29 指向 `develop`，只改动 `frontend/**` 和 `docs/customer/**`。AI 回答页的反馈区域现有“直接采用 / 修改后采用 / 未采用”，选择反馈后才能打开“⭐ 保存优秀案例”。提交使用唯一的真实路径 `POST /platform-api/api/v1/customer-experience-cases`，请求字段为 `store_code`、`product_id`、`sku_id`、`question`、`ai_answer`、`final_answer`、`feedback_type`、`created_by`。

页面采用反馈仍为本页行为；经验案例表单必须让操作人显式选择 `ADOPTED`、`EDITED_ADOPTED`、`CORRECTION`、`ESCALATED` 之一，旧值不得发送或静默映射。成功只接受 C 顶层 `case_id`、`review_status`，且后者必须是 `NEW`、`REVIEWING`、`APPROVED`、`REJECTED`；不读取 `status` 或 `data` 兼容字段，失败不产生本地成功记录。`/experience-cases` 是“我的案例”入口，当前仅展示当前浏览器会话内已获真实 POST 成功响应的最小摘要。不得把问题、AI 回复、最终回复放入 localStorage，也不得用 Mock 伪造提交成功。

C 尚未发布优秀案例 GET 契约；不要自行增加、猜测或调用列表接口。待 C 发布版本化契约和服务后，先做受影响线路评审，再仅补真实 POST/GET 联调记录。前端本地验证：Node `v24.14.0`，`vue-tsc --noEmit`、Vitest 19 文件 / 77 测试、`vite build` 均为 PASS；构建保留单 JS chunk 超过 500 kB 的既有警告。

B-T05 已在 `agent/customer-platform-shell-t05` 完成，Draft PR #25 指向 `develop`。前端入口为 `/`、`/ai-chat`、`/suggestions`、`/suggestions/mine` 与 `/modules/:moduleKey`；AI 客服既有选品、SKU、提问、回答、来源、编辑、复制与反馈链路不可回归。

测试身份只保存 `reporterId`、`reporterName`、`defaultStoreCode`，不是登录或授权；建议正文不得进入 localStorage。页面和交接不得收集或记录客户电话、地址、完整订单号、密码、客户信息或隐私截图。

建议客户端只使用冻结路径 `POST /platform-api/api/v1/customer-suggestions` 和 `GET /platform-api/api/v1/customer-suggestions?reporter_id=`，不回退 Mock。当前 A/C 健康检查为 HTTP 200，但 C 建议查询端点为 HTTP 404；待 C 发布后只补做真实 POST/GET smoke 并记录结果。
