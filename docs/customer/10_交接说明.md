## MVP-PLUS-02 交接

当前分支为 `codex/customer-pilot-experience`，仅改动 `frontend/**` 和 `docs/customer/**`。本任务不改变后端字段、CustomerExperienceCase adapter、共享契约或任何 A/C 网络调用。

首次拥有测试客服身份的进入者会看到“AI客服助手（测试版）”引导：选择商品/SKU、输入客户问题、查看 AI 建议、人工确认后复制发送、好回复可收藏为优秀案例。关闭引导只在本机保存一个已阅读布尔标记；不是认证、权限或培训凭据。

AI 回答页保留原流程和三种反馈。动作展示为 `DIRECT_ANSWER=🟢 可以参考`、`CONTROLLED_ANSWER=🟡 建议确认`、`TRANSFER_HUMAN=🔴 建议人工处理`；不改变 A 返回 action。案例入口文案为“⭐ 收藏为优秀案例”，仍使用既有真实 CustomerExperienceCase POST 和表单中显式选择的冻结经验类型。

选择“未采用”后会出现独立“AI 问题反馈”入口。它打开“为什么未采用？”弹窗，使用 `FACT_ERROR/MISSING_INFO/STYLE_ISSUE/RISK_ISSUE/OTHER`（事实错误/缺少信息/表达问题/风险问题/其他）；`OTHER` 必须填写去标识化说明。该表单调用唯一真实路径 `POST /platform-api/api/v1/ai-response-feedback`，不会发送到经验案例接口，也不会写入 localStorage。

AI 反馈 adapter 严格发送 `store_code/product_id/sku_id/question/ai_answer/feedback_type/feedback_note/final_answer/created_by/context`；context 只含店铺、商品、SKU 且须与顶层一致。每次新反馈会话首次提交携带唯一 `Idempotency-Key`，失败重试复用同一键；成功只接受顶层 `feedback_id/status=NEW`，再显示“反馈已记录。”；失败不会生成本地成功或回退为优秀案例。不要在 B 中增加反馈历史 GET、C Admin/A 导出、状态变更、自动脱敏、Prompt/知识修改或客户/订单操作。

最近验证（2026-07-25）：`vue-tsc --noEmit` PASS；Vitest 22 个文件、87/87 PASS；`vite build` PASS。构建仍有单个 JavaScript chunk 超过 500 kB 的既有警告。

GitHub CLI 浏览器认证已复核恢复；最新 `develop` 基线上的 `1527e2d feat(customer): add AI feedback capture` 已 push，Draft PR [#34](https://github.com/666whatcanisay/AI-Customer-Service-for-Toys/pull/34) 已创建。后续评审只接受冻结协议与真实集成证据；不得以本地 Mock 或浏览器状态宣称 C/A 闭环已完成。

## MVP-PLUS-01 交接

当前分支为 `codex/customer-experience-case-capture`，Draft PR #29 指向 `develop`，只改动 `frontend/**` 和 `docs/customer/**`。AI 回答页的反馈区域现有“直接采用 / 修改后采用 / 未采用”，选择反馈后才能打开“⭐ 保存优秀案例”。提交使用唯一的真实路径 `POST /platform-api/api/v1/customer-experience-cases`，请求字段为 `store_code`、`product_id`、`sku_id`、`question`、`ai_answer`、`final_answer`、`feedback_type`、`created_by`。

C 尚未发布优秀案例 GET 契约；不要自行增加、猜测或调用列表接口。待 C 发布版本化契约和服务后，先做受影响线路评审，再仅补真实 POST/GET 联调记录。前端本地验证：Node `v24.14.0`，`vue-tsc --noEmit`、Vitest 19 文件 / 77 测试、`vite build` 均为 PASS；构建保留单 JS chunk 超过 500 kB 的既有警告。

## MVP-PLUS-02-B-C-SMOKE 交接（2026-07-27）

当前 C 隔离实例已被真实验证：对 `FACT_ERROR`、`MISSING_INFO`、`STYLE_ISSUE`、`RISK_ISSUE`、`OTHER`，带唯一 `Idempotency-Key` 的 POST 均为 HTTP 201，回执含非空 `feedback_id` 与 `status=NEW`；按 `created_by` 的 GET 返回 HTTP 200、`items=5`、`total=5`。所有数据均为合成、去标识化 smoke 数据。

但当前 B `aiResponseFeedbackClient` 未发送 `Idempotency-Key`，五类 B 实际请求形态都收到 C 的 HTTP 422 `AI_RESPONSE_FEEDBACK_VALIDATION_FAILED`。并且 C 的 HTTP 201 回执只有 `feedback_id`、`status`，当前 B adapter 正确要求的 `analysis_status=NEW`、`created_at` 均缺失。因此结论为 `BLOCKED`；失败仅显示失败提示，不会生成本地成功或回退为优秀案例。后续只能在共享契约版本化、兼容性说明和 Affected-line review 完成后统一这两个差异；不要在 B 或 C 单方猜测修改。
