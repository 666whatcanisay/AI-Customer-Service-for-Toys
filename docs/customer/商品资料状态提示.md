# 客服端商品资料状态提示

## 目的

客服在选择店铺、商品和可选 SKU 后，工作台会读取 C 中台提供的紧凑资料状态，帮助客服在生成建议前决定是否需要额外人工核对。

这是一项只读提醒，不是知识发布状态：资料状态为“可供人工参考”不代表已进入 RAG，也不会改变既有 AI 回答、复制、案例沉淀或 AI 问题反馈流程。

## 已冻结的读取边界

客服端仅请求：

`GET /api/v1/customer-knowledge-status?store_code=&product_id=&sku_id=`

正常局域网运行通过同源 `/platform-api` 代理访问；仅在显式设置 `VITE_PLATFORM_API_BASE_URL` 时使用直连排错模式。

前端严格只读取并展示以下字段：

- `status`：`READY`、`NEEDS_REVIEW`、`NO_APPROVED_MATERIAL`、`UNAVAILABLE`；
- `summary`：供客服阅读的中文摘要；
- `last_checked_at`：最近检查时间。

客服端不会读取、缓存或展示原始资料、内容哈希、分析全文、缺口细节、错误 JSON 或技术诊断。

## 客服可见状态

| 状态 | 页面提示 | 客服操作 |
| --- | --- | --- |
| `READY` | 资料可供人工参考 | 仍需核对商品、SKU 和引用后再人工复制。 |
| `NEEDS_REVIEW` | 回复前需要人工核对 | 先按摘要核对商品资料，不作超出资料范围的承诺。 |
| `NO_APPROVED_MATERIAL` | 暂无已审核资料 | 可继续咨询，但不要把资料不足误认为 AI 已有可靠依据。 |
| `UNAVAILABLE` | 资料状态暂不可用 | 按原有人工客服流程核对信息。 |

## 客服页面呈现

客服选择店铺和商品后，页面会固定回显“本次咨询对象”：当前店铺、当前商品和具体款式（SKU）。SKU 不确定时显示“待确认（可留空）”，客服不应猜测款式。

资料卡显示为“AI 参考准备度”，并始终给出一条不改变既有问答流程的“本次操作”提示：

| 页面情况 | 本次操作 |
| --- | --- |
| `READY` | 可继续提问；生成后仍须核对商品、款式和至少一条回答依据。 |
| `NEEDS_REVIEW` | 可继续提问；发送前核对当前商品信息和回答依据，不作超出资料范围的承诺。 |
| `NO_APPROVED_MATERIAL` | 可继续提问；资料不足时不要直接采用，必要时转人工处理。 |
| `UNAVAILABLE` | 可继续提问；按人工客服流程核对商品信息，避免作出承诺。 |
| 查询失败或响应不符合冻结格式 | 页面显示“资料状态暂时无法获取”，明确说明资料状态接口暂时无法连接；可继续生成建议，但必须人工核对。 |

页面同时持续展示完整处理路径：确认店铺、商品和款式 → 保留客户原话并提问 → 核对建议和回答依据 → 修改后人工复制 → （可选）收藏优秀案例或反馈问题。最后一项不替代现有案例/反馈的真实提交和成功回执。

## 异常与不阻断规则

资料状态请求失败、超时或响应不符合冻结格式时，页面只显示：

> 无法获取资料状态，可继续咨询。

该提示不会禁用商品/SKU 选择、AI 问答、回复编辑与复制、优秀案例或 AI 反馈入口；也不会伪造“资料已就绪”或“暂无数据”。

## 验收要点

1. 切换商品或 SKU 后，页面按当前业务范围重新读取状态。
2. 页面没有原始资料、哈希或 AI 分析正文。
3. 资料状态查询失败时，已有客服问答主流程仍可继续。
4. 客服仍须人工确认，系统不自动发送客户消息、不自动发布知识、不自动修改 Prompt 或模型。
5. “暂无已审核资料”是 C 返回的有效业务状态；“资料状态暂时无法获取”是请求或契约失败，两者必须在页面上区分，且都不能阻断咨询。
