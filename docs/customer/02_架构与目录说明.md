# 架构与目录说明

本线只拥有 `frontend/**`、`extension/**`、`docs/customer/**`。B-T03 仅修改 `frontend/**` 与 `docs/customer/**`，没有修改其他线路或共享契约。

前端链路：

```text
AiChat.vue
  → platformClient.ts → platformAdapter.ts → C 店铺/商品/SKU 目录
  → ragClient.ts      → ragAdapter.ts      → A /api/chat
  → errorMapper.ts                          → A/C 分离错误提示
```

- `platformTypes.ts`：冻结的 C 目录页面领域类型。
- `platformAdapter.ts`：只接受 C 顶层 `{items,total}`，不在页面猜测字段。
- `platformClient.ts`：通过 `VITE_PLATFORM_API_BASE_URL` 调用 `/health` 和 `/api/v1` 目录路由。
- `ragTypes.ts`：B-T03 请求固定为 `{question,context}`，context 只有 `tenant_id/platform/store_code/product_id/sku_id`。
- `ragAdapter.ts`：chat 只消费 `data`，严格识别六种动作、风险、来源和回显 context。
- `AiChat.vue`：负责级联选择、切换清理、加载/取消、范围回显校验、回答和人工操作。

生产代码不包含 Mock 回退。Vitest 通过模块 Mock 覆盖组件状态，测试数据不会进入生产请求逻辑。
