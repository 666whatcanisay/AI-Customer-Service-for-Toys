# PILOT-USER-IDENTITY-V1：B 端客服身份选择与来源绑定

## 目标与边界

客服工作台在进入业务页面前，必须从 C 运营后台已创建且启用的客服用户中选择一个身份。B 不再在浏览器中生成 `TESTER-*` 身份，也不保存姓名、店铺或任何密码。

该能力仅用于内部试运行期间追溯案例、AI 问题反馈和效率事件的来源；它不是密码登录、SSO 或正式权限系统。系统仍只生成客服建议，所有对客户的回复都需要人工确认、编辑和复制。

## 客服使用流程

1. 运营人员先在 5174 的“客服用户”中创建并启用用户，绑定至少一个店铺并指定默认店铺。
2. 客服打开 5173，选择 C 返回的启用身份后进入工作台。
3. B 默认加载该身份的默认店铺；店铺选择器只显示已绑定店铺，为未来多店切换保留入口。
4. 收藏经验案例、提交 AI 问题反馈和记录效率事件时，B 将 C 用户 ID 写入既有 `created_by` 或 `operator_id` 字段。

浏览器本地只保留 `{ "userId": "..." }`。刷新时会向 C 重新验证；用户不存在、停用或失去店铺绑定时会清除选择并回到身份选择页，绝不回退到匿名或本地伪造身份。

## 消费的 C 接口

| 用途 | 接口 | B 的约束 |
| --- | --- | --- |
| 身份列表 | `GET /api/v1/customer-identities` | 只接受 `ACTIVE` 用户、默认店铺和至少一个绑定店铺。 |
| 身份恢复 | `GET /api/v1/customer-identities/{user_id}` | 失效、停用或店铺不匹配时清除本地选择。 |
| 经验案例 | `POST /api/v1/customer-experience-cases` | `created_by` 必须是所选 C 用户。 |
| AI 问题反馈 | `POST /api/v1/ai-response-feedback` | `created_by` 必须是所选 C 用户；继续使用现有 `Idempotency-Key`。 |
| 效率事件 | `POST /api/v1/customer-efficiency/events` | 只发送事件元数据，包含 `operator_id`，不发送问题或回答正文。 |

效率事件遵循 `customer-efficiency.v1`：`AI_REQUEST` 先创建交互记录，随后至多记录一次采用或未采用结果；`AI_FEEDBACK_SUBMIT` 仅在 C 返回真实 `feedback_id` 后发送。事件失败会显示提示，但不会伪造案例、反馈或 AI 成功。

- `npm.cmd run build`：通过；保留既有 Vite CJS API、VueUse PURE 注释及大于 500 kB chunk 警告。
- 覆盖身份响应严格解析、停用身份清除、身份选择页、默认/绑定店铺限制、案例/反馈来源字段和效率事件的隐私字段与幂等头。

## 不包含的能力

- 不保存密码，不接入 SSO 或外部认证；
- 不实现复杂 RBAC；角色只由 C 展示并为后续权限设计保留；
- 不自动发送客服消息、不自动退款、不修改订单、不写入 ERP；
- 不保存客户问题、AI 回答或最终回复到效率事件。
