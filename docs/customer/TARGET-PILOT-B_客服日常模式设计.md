# TARGET-PILOT-B 客服日常模式设计

日期：2026-07-27
范围：`frontend/**`、`docs/customer/**`；不修改 AI 核心逻辑、接口协议或共享 contracts。

## Phase 1：现状扫描

已具备店铺/商品/SKU 上下文、真实 RAG 回答、来源、复制、优秀案例和 AI 问题反馈。当前主要阻力不在功能缺失，而在日常连续处理时的上下文与结果切换：

- 新手需要在首页、聊天和反馈说明之间自行拼接“先做什么、何时收藏、何时反馈”。
- 熟练客服在一条回答完成后缺少清晰的“保留商品上下文、处理下一条咨询”入口。
- 高频处理时，编辑下一位客户的问题可能让上一条回答仍停留在页面，增加误复制风险。
- 案例与反馈页虽有入口，但审核状态含义、收藏与反馈的分流理由仍可更直观。
- 服务不可用时已有错误文本，但下一步恢复操作不够集中。

## Phase 2：三种日常模式

| 模式 | 用户需要 | 页面支持 |
| --- | --- | --- |
| 第一次使用 | 不记忆流程也能完成一条咨询 | 首页三步路径，聊天页按步骤展示商品、问题、人工核对。 |
| 熟练使用 | 快速理解回答后该收藏还是反馈 | 回答区保留 action 人工提示和显式采用结果；案例/反馈页解释分流。 |
| 高频使用 | 同一商品连续处理多位客户，避免误用旧回复 | 回答区提供“处理下一条咨询”，保留店铺、商品和 SKU；修改问题时清空旧回答并提示重新生成。 |

## Phase 3：体验决策

- 首页：保留首次三步，引入紧凑的工作节奏说明，不伪造日统计或模板能力。
- 聊天页：只新增本地 UI 状态切换和恢复提示；不改 RAG 请求、商品/SKU 联动、来源、复制、案例或反馈接口。
- 案例页：解释四种审核状态和空状态下一步，不展示未冻结的远端历史。
- 反馈页：解释“收藏优秀案例”和“反馈问题”的边界，继续将真实提交保留在回答区。
- 异常状态：把刷新 AI/商品目录的恢复动作与现有错误说明放在一起；失败仍不产生本地成功。

## 验收边界

- 连续咨询只保留已选上下文，绝不复用旧回答或自动发送。
- 修改客户问题后必须重新生成建议；复制按钮始终只复制当前可见草稿。
- 真正的案例和反馈成功仍只以既有接口回执为准。
- A/RAG 不可用时，真实回答、复制、案例和反馈闭环必须记录为阻塞，而非模拟成功。

## Phase 4-7 验证记录

- 已实现：默认测试店铺自动加载现有真实商品列表；连续咨询使用“处理下一条咨询”时仅保留已选上下文；输入不同的新问题会清空旧回答并提示重新生成。
- 浏览器实际验证：首页、案例页、反馈页和异常恢复入口均正确渲染；C 商品目录返回可选测试商品并可选择。A/RAG 健康检查和实际去标识化咨询请求不可用，故回答、复制、案例与反馈的真实成功闭环为 `BLOCKED`。
- 本地验证：`npm.cmd run typecheck`、Vitest `24 files / 96 tests`、`npm.cmd run build` 均通过。
