# 接口与数据契约

共享契约版本仍为 `contracts/version.json 0.1.0`，B-T03 没有修改 `contracts/**`。以下为总控冻结的任务内兼容约定，不代表公共契约升级。

## C 目录

- Base URL：`VITE_PLATFORM_API_BASE_URL`，开发默认 `http://127.0.0.1:8012`。
- `GET /health`
- `GET /api/v1/test-catalog/stores`
- `GET /api/v1/test-catalog/products?store_code=`
- `GET /api/v1/test-catalog/products/{product_id}/skus`
- 列表只接受顶层 `{items:[...], total:number}`；`data.items` 等别名会作为契约错误停止。
- C 错误：`{error:{code,message,details?},request_id}`。

stores item 固定字段：`tenant_id/platform/store_code/store_name/trial_enabled/knowledge_scope/response_mode/allow_auto_send/test_data_mode/production_usable`。

products item 固定字段：`product_id/platform/store_code/product_name_official/product_name_display/sales_status/age_min/age_max/safety_summary/review_status/publishable`。

skus item 固定字段：`sku_id/product_id/sku_code/sku_name_official/sku_name_display/relation_type/canonical_sku_id/reference_sku_id/component_sku_refs/publishable`，其中 `component_sku_refs` 必须为 `string[]`。

## A 问答

- Base URL：`VITE_RAG_API_BASE_URL`，开发默认 `http://127.0.0.1:8000`。
- `GET /api/health`
- `POST /api/chat`

唯一 B-T03 请求：

```json
{
  "question": "测试问题",
  "context": {
    "tenant_id": "TENANT-PDD-SM-TEST",
    "platform": "pdd",
    "store_code": "PDD-SM",
    "product_id": "PROD-001",
    "sku_id": null
  }
}
```

chat adapter 只消费 `data` 内的 `answer/action/risk_level/sources/warnings/required_fields/model/latency_ms/request_id/context`。action 仅允许 `DIRECT_ANSWER/CONTROLLED_ANSWER/ASK_CLARIFY/REQUIRE_LOOKUP/TRANSFER_HUMAN/REFUSE`。来源固定为 `source_name/page/chunk_id/distance/excerpt/knowledge_version/source_ids/product_id/sku_id`；`source_ids` 必须为 `string[]`。

页面比较响应 `context` 与所选范围；不一致时停止展示回答，防止跨店铺、商品或 SKU 串答。SKU 未选择时发送 `sku_id:null`，只展示 A 返回的 `ASK_CLARIFY`，前端不猜款式。

B-T03-FIX1 已移除初始 PR 中未冻结的目录路径；B 线不保留第二套路由或兼容回退。

## AI-Agent UI-4：AI 控制中心只读消费

本任务未修改 `contracts/**`，也未新增 A/C 接口。以下是对 A-T04 已提供端点的严格前端投影，不代表共享契约升级或增加浏览器权限。

- Base URL：`VITE_RAG_API_BASE_URL`，开发默认 `http://127.0.0.1:8000`。
- `GET /api/admin/ai/modules`：只消费 `data.modules[]` 的 `module_id/name/description/status/implemented`；模块状态仅接受 `PLANNED/DEVELOPING/TESTING/RUNNING/PAUSED/ERROR`。
- `GET /api/admin/ai/modules/ai_customer_service`：只消费模型、ready、知识块数、Prompt 元数据及当前进程指标；`call_count` 的 scope 为 `since_start`，重启后可能重置，不作为历史报表。
- `GET /api/admin/ai/modules/ai_customer_service/prompt`：只消费安全元数据 `prompt_version/prompt_hash/updated_at/source_type/safe_preview/answer_style_rules`；不请求或显示完整 Prompt。
- `GET /api/admin/ai/modules/ai_customer_service/evaluations/latest`：只消费已保存评测摘要 `evaluation_id/executed_at/dataset_version/total_cases/passed_cases/pass_rate/checks/failed_case_ids/report_available`。该端点当前不提供评测快照专属 `model_version/prompt_version`，页面只能标注当前模块元数据，不能将其误称为历史评测版本。
- 未存在浏览器可读、脱敏的 Badcase 分类聚合接口。前端只展示固定分类名称 `FACT_ERROR/MISSING_INFO/STYLE_ISSUE/RISK_ISSUE` 和“暂无数据”，不访问 C 的原始反馈导出接口，不从原文推断计数。
- 所有上述调用出现 HTTP、网络或契约错误时均保留“暂无数据”状态；没有 Mock、示例记录、零值回退或自动重试写操作。

## MVP-PLUS-01：客服经验案例（任务内冻结）

本任务未修改 `contracts/**`。以下是 `experience-case.v1-draft` 的任务内冻结消费约定，不代表共享契约已经发布或升级。

- 请求：`POST /api/v1/customer-experience-cases`。
- 请求体只序列化：`store_code`、`product_id`、`sku_id`、`question`、`ai_answer`、`final_answer`、`feedback_type`、`created_by`。
- `feedback_type` 仅允许 `ADOPTED`、`EDITED_ADOPTED`、`CORRECTION`、`ESCALATED`。页面采用反馈 `DIRECT_ACCEPT`、`EDITED_ACCEPT`、`REJECTED` 只用于本页，表单必须由操作人明确选择经验类型；不得直接发送或静默映射。
- 成功响应只接受顶层 `{case_id, review_status}`，其中 `review_status` 仅允许 `NEW`、`REVIEWING`、`APPROVED`、`REJECTED`。不读取 `status` 或 `data` 兼容别名；缺失、未知状态、网络错误和 HTTP 错误都显示为失败，绝不回退成本地成功或 Mock 成功。
- 查询接口已在任务内冻结为 `GET /api/v1/customer-experience-cases?created_by=&review_status=&page=&size=`；本次 B 修复未扩展远端列表 UI。“我的案例”仍仅显示本次浏览器会话里已经获得真实 POST 成功响应的最小摘要。
- 浏览器会话摘要仅包含店铺、商品、SKU、反馈类型、创建者、状态和提交时间；问题、AI 回答、最终回答不会写入 localStorage 或会话摘要。
- 后续若要提供远端“我的案例”，C 必须按共享契约流程补充 schema、版本、changelog、兼容性说明和受影响线路评审；B 再据已发布契约增加真实 GET adapter 与联调。

## MVP-PLUS-02-FEEDBACK：AIResponseFeedback（任务内冻结）

本任务未修改 `contracts/**`。以下消费总控 `ai-feedback.v1-draft`（`FROZEN_FOR_MVP_PLUS_02_DEVELOPMENT`）的 B 端请求/回执投影，不代表共享 contracts 已升级。

- 请求：`POST /api/v1/ai-response-feedback`；冻结 C 实现还要求每次明确提交携带非空 `Idempotency-Key` 请求头。
- 请求体只序列化：`store_code`、`product_id`、`sku_id`、`question`、`ai_answer`、`feedback_type`、`feedback_note`、`final_answer`、`created_by` 与仅包含三项字段的 `context`。`context` 必须与顶层店铺/商品/SKU 一致。
- `feedback_type` 仅允许 `FACT_ERROR`、`MISSING_INFO`、`STYLE_ISSUE`、`RISK_ISSUE`、`OTHER`。`OTHER` 必须带非空、去标识化的 `feedback_note`；其他类型发送 `null`。`final_answer` 是可空的人工最终回复，不填充虚构文本。
- 成功只接受顶层 `{feedback_id, status}`，且 `status` 必须为 `NEW`。`analysis_status` 与 `created_at` 不属于冻结创建回执，B 不读取或要求它们。缺失字段、未知状态、HTTP/网络错误或 `AI_RESPONSE_FEEDBACK_VALIDATION_FAILED` 都显示为失败，绝不生成本地成功或回退到优秀案例。
- 本任务不增加反馈历史 GET 页面；冻结的查询接口留待后续明确任务处理。
- 真实联调（2026-07-27）：适配后的 B client 为每个新反馈会话生成唯一 `Idempotency-Key`，并在失败重试中复用。五类合成 POST 均收到 HTTP 201、非空 `feedback_id`、`status=NEW`；相同键和相同载荷返回相同 `feedback_id`，GET 返回 `items=5`、`total=5`，未重复创建。`GET /api/v1/ai-response-feedback?created_by=&status=&page=&size=` 已冻结且已验证，但当前页面不需要状态查询，因此不新增历史 UI。
