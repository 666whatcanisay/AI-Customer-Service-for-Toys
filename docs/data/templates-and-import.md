# 模板与导入说明

## 先确认资料，再导入

运营人员的工作是填写业务资料，而不是填写数据库字段。导入前先确认资料属于哪个店铺、商品和 SKU，所有关键说明都有来源，并且没有客户隐私信息。

当前平台已明确支持商品与 SKU 资料的模板下载、预检、导入和错误报告。模板位于 `docs/platform/templates/商品与SKU资料模板.xlsx`，运营中心“导入中心”也提供下载入口。请以运行版本提供的模板为准，不要自行猜测列名或从过期工作表复制隐藏列。

## 商品与 SKU 导入步骤

1. 在运营中心“导入中心”下载模板并阅读表内说明。
2. 先填写店铺、商品、SKU 的业务关联与必要事实；款式有差异时使用独立 SKU，不能把互斥参数合在一个单元格中。
3. 上传后先执行预检。预检只识别格式、关联和可解释错误，不代表资料已发布。
4. 依据识别结果修正缺失、重复、范围不一致或格式问题。
5. 确认后执行导入；导入失败时下载错误报告，逐行修正再提交。
6. 回到商品知识中心核对显示结果与来源范围，再进入后续审核/分析流程。

产品/ SKU 批量入口的实现包含模板、预检、导入与错误报告；FAQ、安全规则和其他资料若在页面中显示模板或占位说明，仍应以实际运行入口与受控资料审核流程为准，不能将“可下载模板”误解成“已存在任意批量写入接口”。

## 受控资料上传

知识资料上传后不直接进入 RAG。其预期过程是：

`RECEIVED → RECOGNIZED → REVIEWING → APPROVED_FOR_ANALYSIS → ANALYZING → ANALYZED`

运营应查看识别摘要、范围、风险和失败原因；批准分析后，AI 可以产生质量分析结果。分析完成不等于发布，也不会自动改变模型、Prompt 或客服可见知识。

## 失败原因处理原则

- **格式问题**：使用最新模板，保留必要标题和范围字段。
- **关联问题**：先创建或核对店铺/商品，再关联 SKU；不要用猜测 ID 硬填。
- **冲突问题**：回到原始资料确认，不以“看起来更合理”的内容覆盖。
- **敏感信息**：删除或去标识化后重新提交，避免把客户信息写入业务资料。
- **系统错误**：保留错误报告和时间，交给维护者检查；不要反复提交或修改数据库文件。
