# 数据资产规范

## 目标与边界

AI-CS 的数据资产服务于受控客服建议和运营审核。资料必须有业务语义、范围和可追溯来源；测试数据、去标识化资料和客户数据不能混用。当前项目不提供 ERP 写入，也不允许将导入资料自动发布为可对客户使用的知识。

## 核心对象

| 对象 | 最低业务信息 | 使用边界 |
| --- | --- | --- |
| 店铺 | `store_code`、店铺名称、来源范围 | 是商品和客服上下文的第一层范围 |
| 商品 | `product_id`、名称、所属店铺、可核验资料 | 客服必须先确定商品再提问 |
| SKU | `sku_id`、所属商品、款式/规格、差异说明 | 已知具体款式时必须选择，避免跨款式回答 |
| FAQ | 问题、可核验答案、适用范围、来源 | 只能回答资料明确覆盖的内容 |
| 安全规则 | 风险、适用条件、警示或人工处理要求、来源 | 优先于营销性表达；不确定时引导人工处理 |
| 知识来源 | 文件元数据、来源定位、校验值、商品/SKU 范围 | 用于审计和核对，不等于自动发布 |

`store_code`、`product_id`、`sku_id` 是跨客服、运营和 AI 的范围锚点。导入、审核、案例和反馈都应保持这些关联；没有明确范围的内容不应被宣称为商品事实。

## 质量规则

1. **完整性**：商品、SKU、FAQ 和安全资料应能说明覆盖范围与缺失项。
2. **一致性**：商品和 SKU 的参数、年龄、警示、包装、款式等冲突时，应进入人工核对，不能由 AI 自行裁定。
3. **可追溯性**：重要结论应能回到受控资料来源、版本或校验值。
4. **最小化**：不得录入真实客户手机号、地址、身份证号、订单号等不必要的个人信息。
5. **人工发布**：被识别、审核或分析的资料，仍要经过明确人工决定才可被视为可用知识。

## 当前测试数据提示

当前内置测试包用于受控验证，启动流程会对重复包做保护性跳过。它不代表真实客户、完整生产目录或可直接对外经营的数据。导入前确认其原始 ZIP、租户与安全标记符合测试用途；不要用解压后重新压缩的目录替代原始包。
